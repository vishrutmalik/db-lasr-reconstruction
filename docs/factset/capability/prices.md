## 1. API identity, transport, authentication

All `DOCUMENTED_OPENAPI` unless tagged otherwise.

- Title: **FactSet Prices API**, version **1.3.1**, OpenAPI 3.0.0. Scope per
  vendor description: "comprehensive global coverage for Equities & Fixed
  Income … Open, High, Low, and Close prices … Reference over **180,000+
  active and inactive securities**." Equity/fund security types include common
  stock, ADR/GDR, preferred, closed/open-ended funds, ETFs; fixed-income types
  include corporates, treasuries/agencies, governments, municipals.
- Server: `https://api.factset.com/content` (single production server; same
  content server as the other families). Content paths are fully prefixed
  `/factset-prices/v1/...`; the batch endpoints live in a **separate shared
  namespace** `/batch/v1/status` and `/batch/v1/result` (NOT under
  `/factset-prices/`) — entitlement/routing implications unknown (part of
  FP-UNRES-04/13).
- Security: **`BasicAuth` only** (HTTP basic; USERNAME-SERIAL + API key with
  IP-range restriction per the 401 text). The spec declares **no OAuth2
  scheme** — unlike Global Prices/Fundamentals/RBICS (CFC-1 pattern: never
  assume a scheme the spec doesn't declare works; SDK 3.0.1 nevertheless ships
  the platform-wide OAuth2 helper, §10 — probe once at smoke).
- **Rate limit: 25 requests per second** — stated in `info.description`
  (bold, vendor's own emphasis). This is the only family in the trial with a
  headline rate limit in the spec itself. No concurrency limit and **no
  exceedance status code** (no 429 anywhere in the spec) are documented
  (FP-UNRES-03).
- Content type: `application/json` only (415 otherwise). No CSV arm exists
  (Global Prices batch-result has one; this one does not).
- Request-line limit: GET URLs limited to **8,192 bytes**; vendor advises POST
  for large id lists (stated in every ids parameter description).
- Read timeout: 400 "The request took too long. Try again with a smaller
  request." documented as fired after **more than 29 seconds** (error-example
  text) — same 29s pattern as five other families (CFC-3).
- Pagination: **none anywhere in this API** (by exhaustion of the parameter
  inventory) — a 200 is the complete result set (CFC-10 conforming).

Notable request-shape facts (DOCUMENTED_OPENAPI):

- **All date parameters are optional everywhere.** Blank start/end/date
  defaults to "previous close" — resolved **per the local region of the
  requested security** (prices GET description, OA page 4627; the
  `/database-rollover` endpoint exists precisely to expose the regional
  "zero dates", §7.5). Contrast: Global Prices requires startDate on
  prices/returns. Mixed-region defaulting behavior is unstated (FP-UNRES-14).
- **Future dates (T+1) are rejected on every dated endpoint** — including
  the date parameters' text on `/dividends`… yet the dividends GET
  *description* says "You may request future dates to receive information for
  declared dividends." Both statements are in the spec; treated as: declared
  future dividends are intended to be servable (FP-UNRES-12 pins live).
- Accepted input ID types everywhere: Market Tickers, SEDOL, ISIN, CUSIP,
  FactSet Permanent IDs (fixed-income: CUSIP-style ids in examples).

### 2.2 Batch processing (2 paths, 4 operations; prices & market-value only)

| Path | Method / operationId | Responses |
|---|---|---|
| `/batch/v1/status` | GET `getBatchStatus` (param `id`: uuid, required) / POST `getBatchStatusWithPost` (body `BatchStatusRequest`) | **201** completed (+`Location: batch/v1/result?id=…`), **202** not finished (examples: `QUEUED`, `EXECUTING`, **`FAILED`**), 404 |
| `/batch/v1/result` | GET `getBatchData` (param `id`) / POST `getBatchDataWithPost` (body `BatchDataRequest`) | **200** `BatchDataResponse`, **202** not finished, 404 |

Async lifecycle (DOCUMENTED_OPENAPI):

1. Submit `/prices` or `/market-value` with `batch=Y` → HTTP **202** with
   `BatchStatusResponse{data:{id, status:"QUEUED", startTime, endTime:null,
   error:null}}` + `Location` header. **The prices `batch` parameter is
   entitlement-gated**: "**Additional Access Required.** To gain access to this
   feature, reach out to your FactSet Account team…" (FP-UNRES-04). Declared
   long-running ceiling: **10 minutes** on the prices `batch` param, **30
   minutes** on the market-value GET `batchOne` param, unstated on the
   market-value POST `BatchOne` schema (FP-DISC-03).
2. Poll status → 202 while `QUEUED`/`EXECUTING`; **201** when `DONE` with
   `Location` → result. `BatchStatus.status` enum: `QUEUED | EXECUTING | DONE |
   FAILED` (uppercase; Global Prices uses lowercase `queued/executing/created/
   failed` — cross-family, a shared poller must normalize). **`FAILED` is
   delivered under HTTP 202** with `error` as a plain string (e.g. "Invalid
   format for startDate") — terminate on status, not HTTP code (CFC-6 pattern).
3. `GET/POST /batch/v1/result` → 200 `BatchDataResponse.data` (required):
   array of `BatchResult` = `oneOf` **2** payload objects (`price`,
   `marketValue`). JSON only — no CSV arm.
4. 404: "The Batch Request was not found. It has probably expired." — retention
   window undocumented (FP-UNRES-05, same as GP-UNRES-07 → FS-VQ-11).
5. Batch timestamps documented as **Eastern Time** but every example carries a
   `Z` (UTC) suffix — FP-DISC-04; pin live before parsing.

## 3. Shared request-parameter semantics

All `DOCUMENTED_OPENAPI`.

### 3.1 Identifiers

Accepted input ID types everywhere: **Market Tickers, SEDOL, ISIN, CUSIP,
FactSet Permanent IDs**. Responses key on:

- `fsymId` — **regional `-R`** on every equity model (price, return, dividend,
  splits, shares, marketValue, highLow, references, returnsSnapshot): "the
  security's best regional security data series per currency … allocated once a
  SEDOL representing the region/currency has been allocated". Nullable.
  Fixed-income rows key on **security-level `-S`** plus `issuerEntityId`
  (**entity `-E`**) — the only sub-family with a different level (CFC-9:
  raw tables must record the level).
- `requestId` — echo of the requested identifier (join key back to the
  caller's universe), on every model.

### 3.2 Dates, frequency, calendar

- `startDate`/`endDate`/`date`: `YYYY-MM-DD`, **all optional**; blank → the
  API "will default to previous close", where "previous close" is the
  **regional zero date of the requested security's local region** (OA 4627;
  §7.5). Future dates (T+1) rejected with 400 "Future Date" (§8; dividends
  forward-looking tension noted in §2.1/FP-UNRES-12).
- `frequency` (prices, returns, shares, market-value; default **D**), 9 values:
  `D` Daily; `W` Weekly (last day of week of the start date); `M` Monthly (last
  trading day); `AM` monthly anchored on start date's day-of-month; `CQ`
  calendar quarterly (last trading day of Mar/Jun/Sep/Dec); **`FQ` Fiscal
  Quarter of the company**; `AY` actual annual (start-date anchored); `CY`
  calendar annual; **`FY` fiscal annual (last trading day of the company's
  fiscal year)**. The fiscal arms have no Global Prices counterpart; there is
  **no `AD` actual-daily arm** — the API offers no documented way to request
  trade-dates-only daily series other than `calendar=LOCAL` (FP-UNRES-09).
- `frequencyFi` (fixed-income; default **D**), 9 values: `D`, `M`, `AM`,
  **`MTD`**, `CQ`, **`CQTD`**, `AY`, `CY`, **`CYTD`** — to-date arms unique to
  the fixed-income endpoint.
- `calendar` (prices, returns, returns-snapshot, shares, market-value,
  high-low; default **FIVEDAY**): `FIVEDAY`, `SEVENDAY` ("includes weekends"),
  `LOCAL` ("the securities' trading calendar which excludes date records for
  respective holiday periods"). **No `US` arm** (Global Prices has one).
  Non-trading-day fill under FIVEDAY is undocumented; the daily-returns example
  contains a 2019-12-25 row with `totalReturn: 0` — INFERRED zero-return fill
  (FP-UNRES-09).

### 3.3 Currency

`currency` (default **Local**) — "Currency code for adjusting prices"; ISO
codes per OA page 1470. Response `currency` reports the delivered currency.
FX source/timing for conversion is undocumented (FP-UNRES-10 — same silence as
GP-UNRES-12/14). No unique-currency-count cap is documented (Global Prices caps
50 — absent here).

### 3.4 Price payload (no field selection, no precision control)

`price` model fields — fixed schema, no `fields` parameter, no `precision`
parameter (Global Prices has both):

- `price` (Closing Price), `priceOpen`, `priceHigh`, `priceLow` — each: "By
  default the price is in local trading currency, **split adjusted and not
  spinoff adjusted. Prices updated nightly at approximately at 9pm ET.**"
  (the 9pm-ET nightly update is the family's only documented
  publication-timing statement — the PIT layer's freshness anchor).
- `volume` — "Returns the **cumulative volume over dates requested**. Data is
  returned in **thousands**." (aggregation semantics at W/M/CQ unpinned,
  FP-UNRES-11; example daily AAPL volume `23563.96` ≈ 23.6M shares —
  consistent with thousands).
- `date` — period ending date; `adjDate` — "Date of last split for which
  prices and volume have been adjusted" (§4.1); `currency`; `fsymId`;
  `requestId`.
- **NOT present: `vwap`, `turnover`, `tradeCount`** — these exist only in
  Global Prices (which is value-suppressed for this account). See §7A.2.

## 4. ADJUSTMENT SEMANTICS (load-bearing) and D-013 basis mapping

### 4.1 What the spec says — exact meanings

`adjust` (prices, dividends, high-low; **default `SPLIT`**),
DOCUMENTED_OPENAPI, quoted meanings (OA page 614 governs, not in inputs):

| Value | Vendor meaning (verbatim) |
|---|---|
| `SPLIT` | "Split ONLY Adjusted. This is used by default." |
| `SPINOFF` | "Splits & Spinoff Adjusted." |
| `DIVADJ` | "Splits, Spinoffs, and Dividends adjusted." |
| `UNSPLIT` | "No Adjustments." (description carries a copy-paste tail, FP-DISC-08) |

Same four-basis structure as Global Prices under different arm names
(`SPINOFF`≈`SPLIT_SPINOFF`, `DIVADJ`≈`DIV_SPIN_SPLITS`). The event-type
composition of the SPINOFF/DIVADJ folds is again unstated
(FP-UNRES-02, twin of GP-UNRES-02 / FS-VQ-29); the spinoff example summary adds
"Spinoffs are **treated as special dividends**" — the only compositional hint
in the document.

Related documented adjustment facts:

- **`adjDate`** is returned on price, return, dividend, shares, and high-low
  rows: "Date of last split for which prices and volume have been adjusted.
  Use /factset-prices/v#/splits endpoint for details." On shares, a missing
  adjDate is the sentinel **`0001-01-01`**. This field is the documented
  **restatement telltale**: it declares which split vintage the returned
  series is restated to — capture it verbatim on every raw row (INFERRED
  consequence: two pulls straddling a split are comparable only via adjDate).
- `/splits`: full history per id; `splitFactor` — "Split adjustment factor for
  n splits ago. A 2-for-1 split returns **.50**, the number you would multiply
  the stock price by" (multiplicative price factor < 1 for forward splits —
  same convention as Global Prices `adjFactor`; the schema's own example value
  `2` contradicts this, FP-DISC-05); `splitComment` — "Description for the
  type of **split or spin off**" (whether spinoffs actually appear in /splits
  is FP-UNRES-15).
- Dividends have their own adjust arm (§6.1): `adjust` on `/dividends`
  controls whether `divsPaid` is split-adjusted (`SPLIT` default) or raw
  (`UNSPLIT`) — the parameter description text speaks of "the prices"
  (copy-paste, FP-DISC-08); the arm's effect on amounts is INFERRED from the
  parameter's presence and must be hand-verified live.
- Shares: `splitAdjust` = `SPLIT` (default) | **`UNSPLIT`** — an **explicit
  unadjusted shares arm exists** (Global Prices has none; GP-UNRES-03's
  restatement trap is directly avoidable here by requesting UNSPLIT shares).
- Returns take **no** `adjust` parameter (split handling implicit; INFERRED
  split-consistent, verify live) but return `adjDate`.

### 4.2 Mapping onto D-013 / provider_contract.md basis conventions

Project law (docs/architecture/provider_contract.md): `CorporateActionBasis ∈
{UNADJUSTED, ADJUSTED, UNKNOWN}`; CT-15 — ADJUSTED-basis price payloads are
REFUSED at canonical build. The adapter must declare:

| API request | Declared basis | Canonical-layer consequence |
|---|---|---|
| `adjust=UNSPLIT` (prices, dividends, high-low), `splitAdjust=UNSPLIT` (shares) | `UNADJUSTED` | **Accepted.** Pair UNSPLIT prices with `/splits` factors + `/dividends` UNSPLIT amounts so the canonical layer computes its own factors. |
| `adjust=SPLIT` (the **default**), `SPINOFF`, `DIVADJ`; `splitAdjust=SPLIT` | `ADJUSTED` | **Refused** by CT-15. Reconciliation fixtures only. |

Consequences (INFERRED from documented behavior + project law):

1. **The vendor default is refuse-worthy — same trap as Global Prices.** An
   adapter that omits `adjust` ships split-adjusted prices; always pass
   `adjust=UNSPLIT` (and `splitAdjust=UNSPLIT`) explicitly and record it in
   the dataset manifest; treat an unspecified adjust as a programming error.
2. **`DIVADJ` prices and all `/returns`/`/returns-snapshot` output are
   vendor-computed conveniences** — cross-checks only under D-013/CT-15, never
   canonical inputs.
3. **Currency**: request `currency=LOCAL` for the canonical arm (FX timing
   undocumented, FP-UNRES-10).
4. **Shares CAN declare UNADJUSTED here** (unlike Global Prices) — but carry
   **no publication-date anchor** (FP-UNRES-06), so the PIT layer must grade
   the shares series by snapshot rules (retrieval-stamped) regardless of the
   basis win. The two families' shares surfaces are complementary: GP has the
   PIT anchor, FP has the unadjusted arm.
5. `RETRO_WINDOW` grading of UNSPLIT daily bars is compatible with D-011
   (bar values publicly knowable at close; vendor states nightly ~9pm-ET
   publication) provided the basis check passes.
6. **`adjDate` must be preserved verbatim on every raw price/shares/dividend
   row** — it is the only documented instrument for detecting restatement
   between pulls.

**Adjustment-semantics verdict:** the API supports the canonical-layer
requirement — a genuinely unadjusted price arm, an unadjusted shares arm, a
multiplicative split-factor history and dated dividend amounts — but the CA
stream here is **dividends+splits only** (no stock distributions, rights,
spin-off factors, or event taxonomy). Full corporate-action reconstruction
still requires Global Prices `/corporate-actions` (which IS entitled per the
audit). The open adjustment questions are the SPINOFF/DIVADJ fold composition
(FP-UNRES-02) and whether spinoffs surface in `/splits` (FP-UNRES-15).

## 5. Returns endpoints — documented vs silent conventions

DOCUMENTED_OPENAPI:

- `/returns`: per-period series at `frequency`, or **rolling cumulative
  returns** via `rollingPeriod` ∈ {1D, 1W, 1M, 3M, 6M, 52W, 2Y, 3Y, 5Y, 10Y}:
  "Period of measure for the rolling cumulative return. This does not change
  display `frequency` but rather the underlying return calculation period. All
  periods are referencing actual periods of measure, not period-ends."
  Output `return` row: `fsymId`, `date` ("End date of the return … could
  represent the entire return period requested"), `adjDate`, `currency`,
  `totalReturn` (double), `requestId`. Calculation methodology: OA page 8748
  (external, not in inputs).
- `dividendAdjust` enum — **default `PRICE`** (5 values): `PRICE` (price
  return, dividends excluded), `EXDATE` / `PAYDATE` (simple TR, unreinvested),
  `EXDATE_C` / `PAYDATE_C` (compound TR, reinvested). Same menu as Global
  Prices but a **different default**: GP defaults to `EXDATE_C`, this API to
  `PRICE` — an adapter that omits the parameter gets *price* returns here and
  *compound total* returns there. Always pass it explicitly (INFERRED rule).
- `/returns-snapshot`: one row per id per `date` with **17 precomputed
  periods** (oneDay, weekToDate, monthToDate, quarterToDate, yearToDate,
  oneMonth, threeMonth, sixMonth, nineMonth, oneYear, then two/three/five/ten/
  twenty/thirtyYearAnnualized, ipoToDateAnnualized — "annualized compound
  total returns"; `ipoToDateAnnualized` "uses the closing price as of the IPO
  date, and not the IPO price itself"). `dividendAdjust` here is the 3-value
  subset `PRICE|EXDATE|EXDATE_C` (default `PRICE`), echoed back per row.

Silent / example-only (FP-UNRES-01 unless noted):

- **Units are never stated.** Example evidence is strong for **percent**:
  52W rolling return `74.47648`; snapshot `oneYear: -14.263678`,
  `yearToDate: 15.517509`; daily rows ±0.03…2.0. Orientation: the daily
  example is captioned "each total Return value is representative of the dates
  return value with dividends reinvested" → per-period at display frequency;
  rolling → cumulative over the rollingPeriod window ending at each period
  end. All INFERRED from examples; must be pinned live with a hand-computable
  case before any use (same battery slot as FS-VQ-31).
- Gross vs net dividend leg inside TR: unstated (the `/dividends` payload
  carries `divsNGFlag`/`divsNGEquiv`, §6.1, so the reconciliation battery can
  test both hypotheses) — fold into FS-VQ-32.
- Split handling inside returns implicit (no adjust param; `adjDate` returned).
- FIVEDAY fill: 2019-12-25 example row with `totalReturn: 0` (FP-UNRES-09).

## 6. Dividends and splits — the family's corporate-action surface

All DOCUMENTED_OPENAPI. **No event taxonomy, no announcement dates, no
adjusted/unadjusted amount matrix, no cancelled-event lever** — this is a
slim CA surface relative to Global Prices `/corporate-actions` (§4A).

### 6.1 `/dividends` payload (per event row)

- Dates: `divsExDate` (ex-date), `divsRecDate` (record), `divsPayDate` (pay).
  **No announcement date** and no knowledge-time stamp of any kind
  (FP-UNRES-12; PIT grading of dividend data: snapshot rules).
- Amounts: `divsPaid` ("Amount of the dividend paid") in the row `currency`,
  under the requested `adjust` arm (§4.1); `divsNGEquiv` — "Net/Gross
  equivalent (**opposite of dividend paid**)" — i.e. the row carries whichever
  of net/gross `divsPaid` is native plus the converse in `divsNGEquiv`.
- Classifiers: `divsTypeC` (integer code) / `divsTypeD` (description) per
  **OA page 8764** (same code table the Global Prices `divTypeCode` uses —
  special-dividend identification path; table not in inputs); `divsTaxC` /
  `divsTaxD` tax markers per OA 15265; `divsNGFlag` enum
  `N | G | T | X | V | 0` (net/gross marker; only N and G glossed via the OA
  link — meanings of T/X/V/0 not in the spec).
- `adjDate` per row (§4.1).
- Declared **future** dividends servable per the GET description (§2.1
  tension); dividend **cancellation/status is not represented at all** —
  unknown whether cancelled events appear (FP-UNRES-12,
  VENDOR_CLARIFICATION_REQUIRED).

### 6.2 `/splits` payload

Full history per id (no date filters): `date` ("**Ex-Date of the split**"),
`splitFactor` (multiplicative, §4.1), `splitComment` (free text, e.g.
"Split: 2 for 1"; GOOGL example "Split: 2 for 1.000968" — the 2014 Class-A/C
distribution expressed as an uneven split), `fsymId`, `requestId`, no adjDate.
Examples show `splitComment: null` for most pre-2003 rows — comment coverage
is not guaranteed (INFERRED from examples).

## 7. Shares, market value, high-low, references, database rollover

All DOCUMENTED_OPENAPI.

### 7.1 `/shares` — security AND company level, base units, UNSPLIT arm

Time series at `frequency`×`calendar`, `splitAdjust` ∈ SPLIT(default)|UNSPLIT:

- `sharesSecurity` — "**Security-level** Common Shares Outstanding in **base
  units**. Shares sourced **primarily from SEC filings**. Securities in
  certain countries will include treasury shares." (OA 10435).
- `sharesCompany` — company-level across all share classes, **non-traded
  excluded**; `sharesCompanyNontraded` — non-traded **included** "by the
  proportion of their nominal or par value" (OA 16867).
- `adjDate` with `0001-01-01` sentinel. **No documentId / reportDate /
  publicationDate / fiscal fields** — the Global Prices shares endpoint's PIT
  anchors are absent here (FP-UNRES-06). Base units (vs GP's inferred
  millions) kill GP-UNRES-11-style ambiguity: AAPL example
  `sharesSecurity: 4443265000`.

### 7.2 `/high-low`

Point-in-period extremes: for a perspective `date` (default previous close)
and `period` ∈ {1D,1W,1M,3M,6M,[YTD GET-only, FP-DISC-14],52W(default),2Y,3Y,
5Y,10Y}, returns `priceHigh`/`priceLow` **with the dates they occurred**
(`priceHighDate`/`priceLowDate`), under `priceType` `CLOSE` (default) or
`INTRADAY` ("if a security price reached an all time high of 10 during trading
hours … but closed that day at 8, INTRADAY returns 10, CLOSE returns 8"),
`adjust` arms as §4.1, plus `adjDate`. Convenience/validation surface — the
INTRADAY arm is the family's only intraday-touching field.

### 7.3 `/market-value` — dated HISTORY at security and entity level

Time series at `frequency`×`calendar`×`currency` over startDate–endDate
(**Global Prices market-value is current-only; this one is a real history**):

- `securityMarketValue` — "share price multiplied by the number of shares at
  the security level. **History is available back to Oct-1999 for North
  American securities, and 1-Jan-2001 for non-North American securities.**"
  (the family's only documented history-depth statement, FP-UNRES-08).
- `entityMarketValue` — aggregate across all share classes **including**
  non-traded shares (valued at the parent equity's price; for ADR-parent
  companies "the price of the ADR is used, but is scaled by the ADR ratio");
  `entityMarketValueExNonTraded` — excluding non-traded (examples misspell the
  key, FP-DISC-06). Values in base units.
- Batch arm available (30-min ceiling per `batchOne`; FP-DISC-03).

### 7.4 `/references` — security master snapshot incl. first/last trade dates

Current-state row per id (no date parameters): `name`, `secType`/
`secTypeCode`/`secTypeCodeDet` (OA 10149), `currency`, `country` (**caveat**:
for North-American-Pricing-database securities returns the country where
*traded*; for Global-Pricing-database securities the country of
*incorporation* — a documented cross-database semantic split), `primaryExchange`
(OA 16610), `exchangeCountry`, `localIndex` (home-country benchmark id, e.g.
`SP50`, OA 10698), `nextTradingHolidayDate` (OA 10397), and:

- `firstDate` — "first date that the FactSet Pricing database began to cover
  the security and **it may not coincide with the actual IPO date**. Pricing
  information … will not be available before the date returned." — the
  documented per-id **history-depth mechanism** (FP-UNRES-08).
- `lastDate` — "last date that the FactSet Pricing database [has] a record for
  this security listing." — combined with the "180,000+ active **and
  inactive** securities" coverage statement (§1), this is the family's
  delisting-adjacent surface (Global Prices documents nothing; GP-UNRES-05 /
  FS-VQ-37). Whether `lastDate` equals the delist date and whether full price
  history is servable for dead ids: FP-UNRES-07, probe with known-delisted ids.

### 7.5 `/database-rollover` — regional zero dates (production trigger)

"Zero relative date and last update time for FactSet databases … in **UTC** …
This relative 'zero' date, meaning **as of yesterday's close**, will vary
across global regions. This API is designed to help production systems …
know when to trigger their processes." One row: `americasRollTime`/
`americasZeroDate`, `asiapacificRollTime`/`asiapacificZeroDate`,
`europeRollTime`/`europeZeroDate`. This is the documented resolver for the
blank-date "previous close" default (§3.2) and the natural nightly-pull
trigger for the ingestion scheduler (INFERRED use). GET and POST are
identical; POST has no body (FP-DISC-09).

## 8. Response and error architecture

DOCUMENTED_OPENAPI:

- Success envelope everywhere: `{ "data": [ ... ] }` (BatchDataResponse marks
  `data` required; content responses do not).
- **One error shape for everything** (vs Global Prices' three):
  `errorResponse` `{status, timestamp, path, message, subErrors{object, field,
  message, rejectedValue[]}}`. `timestamp` format wobbles between
  `YYYY-MM-DD HH:MM:SS.SSS` and ISO-with-Z across examples (FP-DISC-10).
- Documented 400 causes: date format (`YYYY-MM-DD` required), missing required
  parameter ("The parameter 'ids' is required and may not be empty."),
  **future date**, invalid/unknown parameter names ("spelling mistakes and use
  of improper casing"), malformed JSON, read timeout (**>29 seconds**).
- 401 "User Authentication Failed" — bad USERNAME-SERIAL / API key / outside
  the key's IP range.
- 403 — "**USERNAME-SERIAL does not have permission to use
  /factset-prices/v1/{endpoint}**" — endpoint-level wording only; **no per-id
  403 is documented** (unlike Global Prices) and, per the audit's GAP-1
  finding on the sibling family, **entitlement failures can also manifest as
  HTTP 200 value-null shells** — the smoke probe must classify null-shell
  responses as entitlement failures, not data absence (OBSERVED_LIVE pattern
  from the audit, INFERRED applicability here).
- 404 — batch endpoints only ("probably expired", FP-UNRES-05).
- 415 — only `application/json` accepted.
- No 429 / no documented rate-limit exceedance shape despite the documented
  25 rps limit (FP-UNRES-03).

## 10. SDK evidence — transport requirements

All `DOCUMENTED_SDK` (enterprise-sdk GitHub, FactSetPrices v1, SDK 3.0.1):

- **Package/versions**: `fds.sdk.FactSetPrices` **3.0.1** targeting API
  **1.3.1**; Python >= 3.7; OAuth helper in separate package `fds.sdk.utils`.
- **Client construction**: `fds.sdk.FactSetPrices.Configuration(...)` +
  `ApiClient(configuration)` context manager; per-API classes on the client.
- **Auth**: (a) OAuth2 client-credentials via
  `Configuration(fds_oauth_client=ConfidentialClient('/path/app-config.json'))`
  — note the **spec declares BasicAuth only** (§1); OAuth2 against this family
  is SDK-implied, unverified (probe once at smoke, CFC-1 rule); (b) API key via
  `Configuration(username='USERNAME-SERIAL', password='API-KEY')`.
- **API classes / methods** (10 classes, 26 methods, 1:1 with §2 — full map in
  `prices.json` `curated.sdk_method_map`): `PricesApi` (4: security+fixed
  GET/POST), `ReferenceApi` (2), `ReturnsApi` (4: returns + snapshot),
  `DividendsApi` (2), `SplitsApi` (2), `SharesApi` (2), `MarketValueApi` (2),
  `HighLowApi` (2), `DatabaseRolloverApi` (2), `BatchProcessingApi` (4).
- **Dual-status wrapper**: 200/202 (and 201/202) operations return the wrapper —
  `get_status_code()` then `get_response_200()` / `get_response_202()` etc.;
  the batch poller must branch on it, not on exceptions.
- **Async**: generated `*_async` / `*_with_http_info_async` →
  `async_result.get()` (thread-pool style, INFERRED from the OpenAPI-generator
  pattern).
- **Exceptions**: single `fds.sdk.FactSetPrices.ApiException`; dispatch on
  `.status` + body shape (§8).
- **Retries**: opt-in urllib3 `Retry` via `configuration.retries`; **no
  built-in rate-limit handling** — the 25 rps ceiling (§1) must be enforced
  client-side by the transport.
- **No pagination helpers** (API has no pagination). README carries the usual
  `sys.setrecursionlimit(1500)` large-spec import note.
