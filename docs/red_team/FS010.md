Auditor: red-team agent (adversarial). Implementation audited:

## Verdict

**NO_BLOCKING_FINDINGS.**

Every charter surface held under adversarial pressure:

- **Secret leakage:** env-planted sentinel credentials, driven through a success capture,
  an auth failure, a timeout, telemetry, the ledger, a written run manifest, and the auth
  `repr`/`str`, never reach any on-disk artifact or surfaced string. Credential-like
  param keys are refused at request construction, so secrets structurally cannot enter a
  hashed identity or a capture. `FactSetAuthConfig` hides values in both `repr` and `str`.
- **Replay integrity:** cached 403/429/5xx captures are structurally incapable of being
  served as success (direct read, `replay`, and transport cache-first all filter to
  `is_success`); a hand-edited payload or a forged `meta.json` checksum is refused by the
  read-time sha256 check (the capture filename *is* the honest digest, so poisoning needs
  a sha-256 preimage); byte-different drift appends, never overwrites; replay mode builds
  and refuses every entry point offline with `httpx.Client` monkeypatched to explode.
- **Identity/collision:** explicit-default and omitted `inputSymbolType` hash EQUAL via
  the builder; a changed meaningful field (input type, output types) changes the hash; id
  order/dups and output-type order do not; the page coordinate is part of identity. No
  volatile-field exclusion list exists to exploit (batch ids are simply absent from
  `NormalizedRequest`), and the full canonical payload is hashed, so no two different
  wire requests alias to one hash.
- **Budget/gate bypass:** the live gate stays closed on every stop signal combination
  (config-live-false + env-on, either kill switch, padded kill switch, absent env);
  full consent (config `live:true` AND env `FACTSET_LIVE=1` AND no kill switch) is the
  only open state; `build_transport` refuses live when the gate is closed; per-endpoint
  and daily budgets hard-stop sequentially.
- **Data-root evasion:** required-in-live, relative, non-existent, inside-repo,
  repo-subdir-via-`..`, OneDrive/CloudStorage case variants, and symlinks resolving into
  the repo or into a synced path are ALL refused; a genuine external dir is accepted with
  its realpath.
- **Limiter/envelope honesty:** a genuine bad-request 400 classifies as CLIENT (never the
  29s-timeout SPLIT shape); the timeout-as-400 shape is body-classified as SPLIT and is
  surfaced typed WITHOUT a backoff retry; 401/403 separate cleanly; both documented error
  envelopes parse; transient 5xx retries to the attempt cap then raises.
- **Batch resume:** a cached batch RESULT serves cache-first with zero live calls (no
  double-collection); a corrupt/truncated ledger line raises `FactSetIntegrityError`
  rather than resuming garbage; an unresolved submission resumes and a terminal one does
  not.

Three **NON-BLOCKING** findings are ratcheted (two as strict-xfail, one as a pinned
documented behavior). None can leak an env credential, serve a cached error as data, or
open the live gate against a stop signal.

## Non-blocking findings (ratchets)

### RT-FS010-1 — per-endpoint/daily budget is check-then-act, not reserve-before-send

`FactSetTransport.execute` calls `LiveCallLedger.check_budgets` (a read-and-count of the
JSONL ledger) BEFORE the network round-trip, and `record_live_call` only AFTER the
response returns (`transport.py:241-247`, `326-331`). Any request that enters that window
before the first records its `live_call` passes the same budget check, so concurrent /
racing requests can overrun a per-endpoint or daily limit. The ledger `_append` is
lock-guarded, but the check reads without reservation, and across separate processes
(the design's "parallel FS011-16 agents share the ledger") there is no cross-process
reservation at all.

Confirmed deterministically with a re-entrant sender modelling a concurrent arrival:
per-endpoint limit `1`, but **2** live calls executed and recorded.

- Test (strict-xfail, asserts the DESIRED atomic behavior):
  `test_budget_is_atomic_under_racing_requests`.
- Severity rationale (NON-BLOCKING): the overrun is bounded by in-flight concurrency, the
  budget still hard-stops (just late), and it cannot leak secrets or replay errors.
  FS010's own live surface is a single bounded smoke (one request), so the concurrency
  path is not exercised within FS010's scope.
- **Escalation gate:** this MUST become reserve-before-send (append a provisional ledger
  entry / atomic counter under the existing lock, held across check+reserve, with a
  cross-process advisory lock) BEFORE FS011-16 run concurrent live pulls against the
  shared trial quota. The strict-xfail flips to XPASS the moment that fix lands, forcing
  removal of the marker.

### RT-FS010-3 — capture `meta.json` is not routed through the Sanitizer

Telemetry, run manifests, and every raised transport exception pass their strings through
`Sanitizer.clean`/`clean_tree`. The capture-evidence write path (`cache.store`) does NOT:
vendor-supplied quota headers (`_QUOTA_HEADER_PREFIXES` includes `x-factset`) and parsed
error-envelope messages are persisted VERBATIM into `meta.json`.

Confirmed: a 403 whose response carried header `x-factset-user: <sentinel>` left the
sentinel unredacted in `meta.json`, while the identical header emitted to telemetry was
redacted (out-of-tree harness + `test_capture_metadata_is_sanitized_like_telemetry`).

- Test (strict-xfail, asserts the DESIRED symmetric redaction):
  `test_capture_metadata_is_sanitized_like_telemetry`.
- Severity rationale (NON-BLOCKING, defense-in-depth only): the persisted values are
  VENDOR-supplied response metadata, not env-sourced credentials — the transport never
  copies `FACTSET_USERNAME`/`FACTSET_API_KEY` into `meta.json` (proven by
  `test_env_credentials_never_reach_any_artifact_or_surfaced_string`). Real FactSet does
  not echo credentials in `x-factset-*` headers or error bodies, and the file lives under
  the data root, which is validated OUTSIDE git and OneDrive. The raw capture body is
  intentionally verbatim (sanitizing it would break the sha-256 identity), but the
  EXTRACTED metadata (quota headers, parsed messages) in `meta.json` should route through
  the Sanitizer for symmetry with telemetry.

### RT-FS010-2 — `normalize_id_list` dedupes case-sensitively (documented, pinned)

`normalize_id_list` strips and sorts but does not case-fold, so `AAA-US` and `aaa-us`
survive as two ids in one request. This is explicitly NOT the collision the charter warns
about — it never aliases two logical requests to one hash; at worst it sends a
semantically duplicated id to the vendor. tickerRegion casing is a symbology-adapter
policy (FS011 / D-020(b)), not a transport concern. Pinned by
`test_id_dedup_is_case_sensitive_documented` so any future case-folding is a conscious,
reviewed edit.

## Attack log by surface

### Surface 1 — SECRET LEAKAGE (highest priority)

- `test_env_credentials_never_reach_any_artifact_or_surfaced_string`: full-machinery grep
  (success capture, 401, timeout-exhaust, telemetry, ledger, run manifest, `repr`/`str`)
  — zero sentinel hits on disk or in any surfaced string; manifest records presence only.
- `test_credential_like_params_refused_before_caching`: `api_key`/`Authorization`/
  `TOKEN`/`password` param keys refused at `NormalizedRequest` construction.
- `test_auth_dataclass_repr_and_fields_hide_values`: `repr`/`str` value-free.
- (ratchet) `test_capture_metadata_is_sanitized_like_telemetry` — RT-FS010-3.

**Explicit secret-leakage statement:** with sentinel credentials planted in
`FACTSET_USERNAME`/`FACTSET_API_KEY` and driven through requests, captures, telemetry, the
ledger, run manifests, error/exception paths, and dataclass `repr`/`str`, NO sentinel
value appears in any on-disk artifact or any surfaced string. The transport does not
propagate env-sourced credentials into any artifact it writes. The single related
observation (RT-FS010-3) concerns vendor-supplied response metadata, not our credentials,
and is defense-in-depth only.

## Notes on residual risk (non-actionable for FS010)

- N-1: the storage cap (`_store_guarded`) and the disk-reserve check share the same
  check-then-act shape as RT-FS010-1; the in-memory `_storage_used` counter also drifts
  from reality because ledger/telemetry writes are not counted against the cap after
  construction. Bounded and non-security; folded into the RT-FS010-1 reserve-before-send
  escalation.
- N-2: `httpx` exceptions outside `TimeoutException`/`TransportError` (e.g. `InvalidURL`)
  propagate from `HttpxSender.send` without passing through the transport sanitizer. Those
  exception strings do not contain credentials (Basic auth lives in headers, never the
  URL), so this is noted, not filed.
