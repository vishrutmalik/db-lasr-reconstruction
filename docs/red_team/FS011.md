## Governing identity invariants

The attack surface was derived independently from the FS011 charter,
architecture §5, the MANIFEST identity semantics and FS-VQ-23..28, and
findings F-009..F-013:

- request and response identity schemes must remain caller-declared and
  consistent at every boundary;
- fsym entity/security/regional/listing levels are distinct types, not
  interchangeable strings;
- one canonical identifier must have one cache identity and one normalized
  collision key;
- every requested identifier must be mapped or explained in exactly one of
  seven accounting categories;
- effective intervals must be structurally valid and must not permit
  overlapping ownership by different securities;
- a legacy bridge must fall back when dated evidence is absent,
  contradictory, or ambiguous;
- HTTP 403 evidence is `not_entitled`/`UNRESOLVED`, never content evidence.

## Blocking findings

### RT-FS011-01 — mapping accounting can report success for discarded rows

**Corroborates VF-FS011-1; blocker.** A current row containing only a valid
`fsymEntityId` is accounted `successfully_retrieved`, but `seed_securities`
emits no security. The historical analogue counts a non-null value with null
`outputType` as success, after which hydration silently skips it. Both create
a false mapped-or-explained result. Operation-specific success must require
the identity needed by the operation, or the row must receive a non-success
typed category.

### RT-FS011-02 — response scheme and fsym-level confusion cross the boundary

**Corroborates and extends VF-FS011-2; blocker.** Current and historical rows
with missing or mismatched `inputSymbolType` are accepted. In addition,
current `fsymSecurityId` outputs bearing `-E`, `-R`, or `-L` level suffixes
are counted as successful by `resolve_current`. A later seed or bridge might
raise, but raw current resolution and cross-scheme checks can already consume
the false success. Validate the scheme echo and every non-null requested
output at the adapter boundary before accounting or returning rows.

### RT-FS011-03 — historical casing and structure evade collision checks

**Corroborates VF-FS011-3; blocker.** `IdentifierInterval` accepts empty or
unknown schemes, blank/malformed values, and lowercase identifiers. The map
therefore treats overlapping `ticker:alfa-us` and `ticker:ALFA-US` as
different claims. Map each documented historical `outputType` to its canonical
scheme, normalize and structurally validate the value, and use that canonical
pair for storage and duplicate detection.

### RT-FS011-04 — inverted effective intervals weaken overlap integrity

**Corroborates VF-FS011-4; blocker.** ISO-valid bounds with
`startDate > endDate` are accepted. An inverted interval can make the overlap
predicate return false and allow conflicting ownership. Quarantine inverted
bounds while preserving valid raw date strings and the conservative unknown
open-end convention.

### RT-FS011-05 — conflicting fsym re-seeds are silently discarded

**Corroborates VF-FS011-5; blocker.** Re-seeding the same
`fsymSecurityId` with a different entity edge returns the first seed. The same
hazard applies to regional and listing edges. Only an equivalent identity
reassertion may be idempotent; contradictory structural edges require a typed
integrity refusal. Enrichment-only differences can follow an explicit policy,
but must not mask identity-edge disagreement.

### RT-FS011-06 — historical responses can inject unrequested output schemes

**New adjacent blocker.** A request limited to `tickerRegion` accepts a CUSIP
row because the historical parser is not given the requested output set and
the adapter validates only whether the output type is globally documented.
`hydrate_identity_map` can consequently store identity evidence that was
never requested under this cache identity. Check each row's `outputType`
case-insensitively against the exact request output set before accounting or
hydration.

### RT-FS011-07 — contradictory covering intervals can still authorize a bridge

**New adjacent blocker.** When two historical tickerRegion intervals cover
the retrieval date, one matching the legacy ticker and one carrying a
different ticker, `evaluate_bridge` accepts the matching row and mints the
fsym identity. The evidence is ambiguous, so the bridge must not silently
pick the favorable row. Require unambiguous dated agreement; contradictory
covering claims must produce a typed legacy-v1 fallback (or a typed integrity
refusal that the caller converts to that fallback).

## Non-blocking hardening observation

### RT-FS011-08 — exact duplicate current rows escape raw grain control

Conflicting duplicate current rows already raise, but byte-equivalent rows
are returned twice. Seeding is mostly idempotent, yet duplicate raw grain can
inflate downstream work and violates the no-silent-multiplicity posture.
Reject or deterministically collapse exact duplicates. This is hardening, not
an independent acceptance blocker, because the duplicate carries no competing
identity claim.

## Controls that held

- A forced v2 digest collision between two distinct fsym securities raises
  `DuplicateIdentityError`; the test does not claim a 48-bit truncated digest
  is mathematically collision-free.
- 101 identifiers split into two chunks retain 100 `not_entitled` outcomes
  for a synthetic first-chunk 403 and one independent success for the second
  chunk. The failure reason remains chunk evidence.
- duplicate, reordered, mixed-case caller identifiers create one canonical
  sorted request and two accounting keys, not extra quota/cache identities;
- incomplete accounting and a second assignment to the same key both refuse;
- historical 403 accounting remains `UNRESOLVED`, with `not_entitled=1`; it
  is not mutated into a content pass or failure.

## Historical entitlement ruling

F-011's observed split remains decisive: current resolution was observed as
HTTP 200, while historical resolution was observed as HTTP 403. The classifier
is correct to emit `PASS_WITH_UNRESOLVED` for that shape. It proves neither
incorrect historical content nor compliant historical content. Under the
unchanged FS011 acceptance charter, historical ticker-change and duplicate
content must be observed green; therefore the 403 leaves the acceptance gate
**open and blocking**. Only a green entitled historical battery or an explicit
orchestrator/user charter amendment can close that gate.

### RT-FS011-09 — conflicting case variants of one output key are last-wins

**Round-two blocker.** A current row can carry both
`fsymSecurityId=AAAAAA-S` and `FSYMSECURITYID=BBBBBB-S`. The parser's
case-folding dictionary comprehension erases the first key before typed output
validation, and resolution accepts one security. The null/non-null variant is
also accepted. Equivalent duplicates may collapse, but different values for
the same logical case-insensitive key must raise a typed integrity or
ambiguity error before a security is selected.

Round-two code gate: **FAIL pending RT-FS011-09 remediation.** Separately, the
historical entitlement/live-content gate remains blocked exactly as ruled
above; fixing RT-FS011-09 cannot turn unobserved historical content green.

Two supplemental probes remain non-blocking hardening observations. Exact
duplicate historical rows survive in the raw `HistoricalResolution` tuple
(the map later collapses an equivalent interval), so raw historical grain is
not yet symmetric with the fixed current-row dedupe. Also, punctuation-only
ticker tokens such as `--US` and `.-US` satisfy the present structural regex.
They should be tightened if the documented vendor ticker grammar excludes
them; neither probe supplied a competing identity or false bridge in this
round, so neither is promoted to a separate acceptance blocker.
