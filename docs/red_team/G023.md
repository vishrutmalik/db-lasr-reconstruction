## Verdict

**0 BLOCKING findings.** 2 ratcheted non-blocking defects (RT-G023-1,
RT-G023-2), 3 non-blocking notes, 6 recorded observations. The core label
machinery survived every attack aimed at fabricating alpha: window
anchoring is execution-based in all four modes (independently recomputed
for P4's t+2 MOC), the fit boundary is a hard skip with coherent `<=`
semantics against the PIT gate, unknowable terminal returns can neither
enter a label nor leak through pool means, the vol window provably never
reads past the decision close, purged retention tiles in time even across
a vanished calendar month, and the build is byte-deterministic under
hash-seed stress. Both ratcheted defects live on non-evidenced /
degenerate configuration edges; neither can contaminate the four evidenced
family configs as shipped. They must be fixed before the `close_to_open`
basis variant is ever run through CV (RT-1) and before G026 treats the
skip ledger as a complete account of the grid (RT-2).

## Findings

### RT-G023-1 — `close_to_open` labels share real return segments while stamped CLEAN (NON-BLOCKING, ratcheted; must fix before that basis is ever used)

`_point_timing` ends a `close_to_open` window at the open FOLLOWING the
(shifted) end grid point, i.e. one trading day past where the next
window starts. Adjacent 1W/1M labels therefore genuinely share an
overnight — across a weekend, close Fri → open Mon, an entire 2-day gap —
yet `OverlapMetadata`/`purge_status` are computed purely from grid-step
distance (`|i−j| < H`), so H=1 families report `CLEAN`, multiplicity 1,
`overlap_set_size` 0, `embargo_steps` 0. Smoking gun (probe 1b′/keeper):
a stock whose only price move is one weekend gap produces two adjacent
"non-overlapping, CLEAN" labels that each fully realize the SAME +30 %
move. For H>1 `close_to_open` families the true shared span exceeds the
recorded `max_shared_steps` by the same overnight. Any fold purge/embargo
keyed on this metadata leaks shared outcomes across the train/test
boundary (CI-015's exact failure mode).

Why non-blocking: `close_to_open` is never a `DEFAULT_BASIS`, no evidenced
family config uses it (it exists as the explicit MP §19.3 variant), and
G026 does not consume the metadata yet. It becomes blocking the moment a
`close_to_open` config is run through validation. Fix direction: compute
overlap facts from the actual `[target_start, target_end]` stamps (or add
one grid step of purge/embargo for end-extending bases).

Ratchet: `test_rt1_close_to_open_metadata_must_admit_real_time_overlap`
(strict xfail; flips on fix).

### RT-G023-2 — empty-universe decision dates vanish silently from the ledger (NON-BLOCKING, ratcheted)

`_build_grid_point` iterates `sorted(set(universe(as_of)))`; when the
resolver returns an empty set the retained grid point produces zero
records AND zero skip events — `candidates != emitted + skipped`, in
direct tension with the module's "auditable non-emission, never a silent
drop" contract (`SkipEvent` docstring). Every other vanishing mode is
ledgered (point-level: unrealized/lag/calendar/purged; security-level:
group/price/FX). An upstream universe bug (e.g. a broken membership join
returning empty on some dates) would silently thin the training set with
no auditable trace except a `grid` vs `emitted_grid` diff. Reproduction:
probe 6a; ratchet `test_rt2_empty_universe_decision_is_ledgered` (strict
xfail).

### RT-G023-N3 — `overlap_set_size` is approximate in both directions (NON-BLOCKING note)

(a) It counts retained-but-zero-emission grid points (probe 5d: 3 claimed
vs 2 actually emitting) — the field's docstring says "emitted grid points
with intersecting windows". (b) It is scoped to the current build's
`[window_start, window_end]` (probe 7b: same April 3M point reports 0 in a
narrow build, 4 in a wide one); genuinely overlapping points outside the
window are invisible. `purge_horizon_steps`/`embargo_steps`/`horizon_steps`
are exact grid constants and are the fields fold purging must key on;
G026 must NOT derive purge decisions from `overlap_set_size`. Fix is a
docstring/semantics clarification or post-emission recomputation.

### RT-G023-N4 — no dedicated runtime flag for the SAME_CLOSE look-ahead (NON-BLOCKING note)

The acknowledged P1 look-ahead is discoverable (mode in config and in the
INFO build log; truthful `execution_time == decision_time` stamps) but
there is no WARNING banner analogous to the zero-borrow banner the skill
checklist expects for unrealistic-execution modes. A consumer aggregating
results could mix SAME_CLOSE labels with tradable-mode labels without any
loud signal. Suggest a `logger.warning` (or a record-level flag) when
`execution_mode == same_close`.

### RT-G023-N5 — `MarketDataView.from_records` is last-write-wins on duplicate keys (NON-BLOCKING, fixture-only)

Two price rows for the same `(security_id, event_date)` with conflicting
values yield input-order-dependent labels (probe 6d: s01 `+50 %/+1` vs
`+1 %/−1`). Unreachable through the sanctioned path: `prices_daily` PK
uniqueness is enforced by schema validation upstream and `as_of_frame`
serves validated datasets (vintaged tables additionally dedup to latest
vintage). Risk is confined to direct `from_records` fixture callers; a
cheap duplicate-key guard would close it.

## Observations (no defect; recorded for the registers)

- **O-1 (ties are ordinal):** `pctrank` gives tied values DISTINCT ranks
  0..1 ordered by `security_id` (documented `stable_sort` rule), so an
  all-equal residual pool labels ±1 purely by ticker — deterministic and
  shuffle-invariant (probe 4c keeper), but a departure from average-rank
  conventions worth a register entry if P4 comparisons ever hinge on tie
  handling.
- **O-2 (tiny-pool rule divergence):** quantile families label nothing
  below n=4 (`floor(0.3·n)=0`); the P4 threshold rule labels ±1 at n=2/3.
  Both per-paper; cells of size 2–3 behave qualitatively differently
  across families.
- **O-3 (grid-step horizons stretch in calendar time):** with a whole
  month of no trading days, a "3M" window spans 4 calendar months
  (probe 5a) — grid-space overlap/purge stays exactly correct (time
  overlap == step predicate; purged windows tile), but CI-013's calendar
  reading degrades on pathological calendars.
- **O-4 (halt-spanning delistings enter no label):** if a stock's last
  trade is inside window *i* but the delisting effective date falls after
  window *i*'s end, window *i* skips (`missing_end_price` — its outcome
  was genuinely unresolved at window end) and window *i+1* skips
  (`missing_start_price` — untradeable at execution): the crash-to-
  delisting outcome appears in NO training label (probe 8b). This is the
  PIT-honest reading (the alternative injects post-window information into
  a fixed-horizon label), but it systematically removes the most extreme
  losers from the label distribution for halt-then-delist events; G026's
  backtester must still realize the terminal return on the HELD position
  (LT-009/LT-018 territory), and the choice deserves an assumptions-
  register entry.
- **O-5 (boundary coherence):** emit-at-equality (`target_end ==
  build_as_of`) is exactly consistent with the PIT `<=` include boundary
  verified in the G020 audit; no window can emit while its end price is
  unknowable (probes 2a/2b keeper).
- **O-6 (training-lag gate granularity):** the P3-23 lag gate compares
  grid indices via `grid_index_at_or_before(grid, build_as_of.date())`,
  ignoring time-of-day; immaterial because the UNREALIZED gate (full
  timestamps) dominates every near-boundary point.
