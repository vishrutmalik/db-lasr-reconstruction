## Findings

### RT-G024-1 — BLOCKING: min-Z selection ranks factors by coverage before signal (A-G024-03 quantified)

**Mechanism.** `z_statistic` (P1 formulas §3) sums `√(W⁺ⱼW⁻ⱼ)` over the
fitted masses; `fit_factor` drops missing-rank rows from the bins
(CI-021), so `Σⱼ(W⁺ⱼ+W⁻ⱼ) = covered_mass < 1` under partial coverage and
`Z ≤ covered_mass/2` by AM-GM **regardless of content**. The paper's own
precondition ("Since weights sum to 1, Σⱼ(W⁺ⱼ+W⁻ⱼ)=1", formulas §1)
silently fails, so paper-faithfulness cannot be claimed for this regime
either. The proper AdaBoost round normalizer for the fitted h with h=0 on
uncovered rows is `Z_true = 2·Σⱼ√(W⁺ⱼW⁻ⱼ) + uncovered_mass`, which is
coverage-honest.

**Quantification** (shipped config: Q=5, raw Z, h_zero, ε=1/N; n=1000):

| probe | result |
|---|---|
| noise@50% cov vs weak signal@100% (50 seeds) | noise wins **50/50** (mean Z 0.2490 vs 0.4965) |
| coverage sweep | Z(noise) ≈ cov/2; wins 25/25 at cov ≤ 0.98; **21/25 at cov = 0.99** |
| 30-round boost {signal, noise@50%} | noise selected **30/30**; OOS corr(H,label) 0.0021 vs 0.0715 signal-only |
| coverage-honest `Z_true` on the same panels | signal wins 50/50 (fix restores correct selection) |
| teeth: equal coverage | signal wins 50/50 (defect, not construction, drives the flips) |
| survival threshold | a full-coverage factor needs raw Z < 0.25 to beat 50%-coverage noise — near-perfect class separation, far beyond any realistic factor (real monthly factors sit ~0.49+; the paper's own worked example's best factor is 0.4 with Q=2) |

**In-PR exposure (why BLOCKING, not a future-goal hazard).** The G022
library ships `DEFAULT_MIN_COVERAGE = 0.5`, and the PR's own integration
smoke (`tests/unit/test_models_training_smoke.py`, WORLD_SEED=1729)
builds a TrainingMatrix whose columns have coverage
momentum_12_1 = 100/142 (70.4%), reversal_1m = 100/142 (70.4%),
size_neg_log_mcap = 142/142 (100%). Measured on that exact matrix:
round-1 raw Z = 0.3507/0.3452/0.4880 → the boost selects
momentum 16 + reversal 14 = 30/30 rounds and size **0/30**, while the
coverage-honest normalizer says size is the MOST discriminative
(Z_true 0.9760) and the two selected factors are nearly useless
(0.9972/0.9862). The first multi-factor model this repo ever trains has
coverage-artifact selection; every downstream consumer of
`boost`+`MinZObjective` (G025 pooled windows, G029/G030, ensembles)
inherits it, and the recorded `selection_scores` (implausibly low Z)
present the artifact as strong discrimination — the exact
strong-results-as-bugs channel of MP §10.8.

**Required to clear** (any one, plus a decisions.md entry — an
assumptions-register line + "G037 audit item" is not containment for a
defect this PR already triggers):
1. coverage-honest objective (score `2Z + uncovered_mass`, or
   equivalently penalize by missing mass) behind the existing config
   surface, with an A/B test; or
2. a hard guard: raw min-Z refuses (or hard-warns via a typed event)
   TrainingMatrix inputs with unequal/partial column coverage; or
3. a full-coverage precondition enforced at TrainingMatrix construction
   for the min_z-raw configuration, with missing-data policy resolved
   upstream.

```python
import numpy as np
from lasr.models.nlasr.kernel import PiecewiseConstantBinKernel
from lasr.models.selection import z_statistic
rng = np.random.default_rng(7); n = 1000
y = np.array([1,-1]*(n//2), dtype=np.int8); rng.shuffle(y)
def rk(v):
    o = np.full(v.shape, np.nan); m = np.isfinite(v)
    o[m] = (np.argsort(np.argsort(v[m]))+1)/m.sum(); return o
sig = rk(0.10*y + rng.standard_normal(n))          # real signal, 100% cov
noi = rng.standard_normal(n); noi[rng.choice(n, n//2, False)] = np.nan
noi = rk(noi)                                      # pure noise, 50% cov
k = PiecewiseConstantBinKernel(n_bins=5); w = np.full(n, 1/n)
for name, col in (("signal", sig), ("noise50", noi)):
    m = k.fit_factor(col, y, w, factor_id=name).masses()
    print(name, round(z_statistic(m.w_pos, m.w_neg), 4))
# signal ~0.49..., noise50 ~0.24...  -> argmin picks the noise
```

### RT-G024-2 — NON-BLOCKING: `propagate_nan` + missing training value fails with a message that hides the cause (= verifier NB-1)

With `missing_policy="propagate_nan"` (the OQ-P1-05 declared alternative)
and ANY NaN rank in the training pool, the selected factor's h is NaN,
`exp_reweight` poisons the weights, and the loop dies with
`BoostingError: weight mass must be finite and positive to renormalize,
got nan` — loud (good: never silent), but the message names neither the
missing rank, the factor, nor the policy; the config leaf is named
`missing_at_predict` yet governs the TRAINING update (A-G024-04 documents
the h_zero extension only). Under this policy the model cannot train on
partial coverage at all — undocumented. Keeper pins the never-silent
invariant: `TestMissingPolicyInTraining`.

### N-1 — NON-BLOCKING note: unstamped `FittedModel` carries no PIT guarantee outside G026

The CI-006 fields are optional-but-validated (documented: "formula-level
tests may omit them"). Verified on the G026 branch that the walk-forward
runner both stamps them from fold data and refuses violations
(`LeakageRefusalError`; `runner.py` asserts the stamp is present). The
residual risk is any FUTURE non-G026 production caller constructing
`FittedModel` directly without stamps — no G024-side gate exists. Fine as
a two-sided contract today; G037 should check that every production
artifact writer stamps.
