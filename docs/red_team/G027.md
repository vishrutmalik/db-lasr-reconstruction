## Findings

### RT-G027-1 — exact-fit residualization scales float rounding noise into a full-gross book, silently (NON-BLOCKING, ratcheted; must fix before Level-2 runs on small universes or degenerate/synthetic score vectors)

When the OLS fit in `residualize` is exact — ALWAYS for a 2-name
`per_leg` leg, and for `joint`/`per_leg` whenever scores are affine in
beta over the fitted set — every residual is mathematically zero, but
floating-point rounding leaves ±1e-16-scale noise with arbitrary signs.
The sign-following scaler (A-G027-02: "positions follow the sign of the
weighting score", "exactly 0.0 is no position") then normalizes each
side by the noise total, producing FULL-SIZE positions out of nothing:

```python
ids = [f"n{i:02d}" for i in range(11)]           # quintiles → legs of 3 and 2
scores = {s: float(i) for i, s in enumerate(ids)}
beta = {s: 0.5 + 0.09 * i for i, s in enumerate(ids)}   # scores ≡ affine(beta)
book = build_signal_weighted_portfolio(scores,
    SignalWeightedSpec(n_fractiles=5, gross_exposure=2.0,
                       beta_residualization="per_leg"), beta=beta)
# residuals: {-1.1e-16, 0.0, +1.1e-16, -1.1e-16, +1.1e-16}
# book:      n00 -0.50, n02 +0.50, n09 -0.50, n10 +0.50   (!!)
```

A ±50%-per-name, gross-2.0 book whose entire composition — which names,
which SIDE — is decided by rounding error, with no warning and no error.
The two typed guards on either side of this edge
(`DegenerateLegError` for all-exactly-zero / one-sided;
the A-G027-07 zero-beta-variance fallback) both miss it: whether you get
the typed error or the noise book depends on float luck (probe E2a vs
E2b: same mechanism, opposite outcomes). Deterministic, so no
reproducibility issue, and a noise book has ~zero expected alpha — the
risk is fabricated EXPOSURE (full gross on nothing) in any small-universe
or synthetic-scenario run, e.g. an LT battery cell. Unreachable for
evidenced configs (P4 quintile legs are hundreds of names; real scores
are never exactly collinear with betas).

Fix direction: treat |residual| below a relative epsilon of the selected
set's score scale as exactly 0.0 before the sign split (which routes
exact-fit legs into the existing `DegenerateLegError` / no-position
paths). Ratchet:
`test_exact_fit_residual_noise_must_not_build_a_book` (strict xfail;
flips on fix). Pass-side keeper:
`test_per_leg_two_name_legs_both_exact_fit_is_typed`.

### RT-G027-2 — the CI-045 runtime gate cannot see a cash-ledger hole; the docstring's "two ways" are not independent (NON-BLOCKING note; shipped accounting verified correct)

`run_accounting`'s residual compares `net_pnl/nav_start` (net_pnl = Σ
step P&L contributions − cost − borrow) against `Σ w·(F−1) −
(cost+borrow)/nav_start`. Both legs derive from the same `positions` ×
`returns` state; the `cash` variable — trades, cost, borrow, and
termination credits — is a third derivation that NO runtime check
touches. Teeth demonstration (probe C4, source-clone, production
untouched): deleting the single line `cash += value` in the termination
branch fabricates +$600 of `final_nav` on a $1000 fixture while **every
period row reconciles** (residuals ≤ 5.6e-17, per-period returns
bit-identical to the correct run); `N0·Π(1+r_t)` then disagrees with
`final_nav` by exactly $600 and nothing raises. The module docstring's
claim of "a currency cash-ledger path and a weighted-return
recomputation" overstates the gate.

Compounding the gap: the implementer's random-panel property test
(`TestPropertyReconciliation`) asserts `nav_end == nav_start + net_pnl`
— but its panels never terminate anything (`set()` throughout), so the
one test that would catch this defect class never exercises the
termination cash path (the hand fixture does, at one point).

Why non-blocking: the SHIPPED code is correct — this audit re-derived
the full NAV chain (returns, turnover, final NAV) with an independent
simulator on termination-heavy random panels and everything matches to
1e-11 (keeper `TestIndependentNavChain`, 5 seeds, ≥3 terminations each,
plus a survivorship-teeth check that zeroing terminal legs CHANGES the
result). Fix direction: assert `|nav_end − (nav_start + net_pnl)| ≤ tol
· max(1, nav_end)` inside the engine each period (cheap, closes the
whole class), and add terminations to the property test. The keeper
closes the coverage gap durably on the leakage side regardless.

### RT-G027-3 — reconciliation tolerance: engine 1e-9 vs CI-045's written 1e-10, with a real (if absurd) divergence regime (NON-BLOCKING note; = verifier N-1 + quantification)

`RECONCILIATION_TOLERANCE = 1e-9` is 10× looser than the criterion text.
Measured: residuals scale with period-return magnitude (they are
absolute, in return units) — gross-1e7..3e7 long-only books produce
residuals 2.3e-10..4.7e-10 that violate CI-045-as-written while passing
the runtime gate; gross 1e8 false-fires the gate on a mathematically
valid book. Every realistic regime is safe by ~6 orders of magnitude
(worst 2.6e-16 over 200 random panels; 3.8e-19 under the 10k-name NAV-
1e12 scale attack — `fsum` leaves no rounding-accumulation room, so the
"many tiny errors under the gate" attack fails). Align the constant or
document the divergence; nothing is gameable at evidenced scales.
Keeper: `test_10k_names_nav_1e12_residual_below_ci045` pins the
scale-attack residual below the WRITTEN 1e-10.

### RT-G027-4 — a −100% return without a terminal event silently closes the position and bypasses the re-entry ban (NON-BLOCKING, ratcheted; = verifier N-5, sharpened)

`positions` drops exact-zero values after each step, so r = −1.0 with no
`terminated` marker closes the position with no `TerminationRecord`, no
`MissingReturnError` on later steps (the id is simply no longer held) —
and no entry in `terminated_ever`, so the id may re-enter a later target
and trade again (probed: re-entered and booked +100%). P&L is correct
throughout (the −100% is realized once; no phantom), but a data layer
that delivers a delisting as a bare −1.0 return instead of a terminal
step silently evades CI-049's exactly-once ban and the audit trail.
A-G023-08 makes G023's machinery emit terminal steps, so the sanctioned
path is safe; the edge needs either a typed rejection of −1.0-without-
terminal or an automatic ban. Ratchet:
`test_wipeout_without_terminal_event_must_not_reenter` (strict xfail).

### RT-G027-5 — negative cost/borrow from the hook is accepted silently: a NAV-fabrication channel (NON-BLOCKING, ratcheted)

`period_charges` output is validated for finiteness only. A cost model
returning `(−50.0, −25.0)` ADDS $75 to cash — +7.5% period return on
zero-return marks, no warning, no typed error (probe D4). The CI-048
rates are all non-negative and G034's configs validate `>= 0`, so only a
buggy/malicious CostModel triggers it — but the engine's own contract
("either component may be 0.0") implies a sign convention it never
enforces, and this is the single easiest way to fabricate Sharpe through
this module. Fix: reject negative components (or explicitly document
rebates as in-scope with a signed convention). Ratchet:
`test_negative_charges_are_rejected` (strict xfail).

### RT-G027-6 — `Portfolio` (and `Ledger.final_positions`) are only shallowly frozen (NON-BLOCKING, ratcheted hardening)

`Portfolio` is a frozen dataclass but canonicalizes `weights` into a
plain `dict`; `book.weights["A"] = 0.99` mutates the "frozen" book in
place and the `gross`/`net` properties recompute on the mutated state
(probe F3: declared gross_target 1.0, post-mutation gross 1.49).
`Ledger.final_positions` is likewise a caller-writable plain dict.
No production path mutates them today; a `MappingProxyType` wrap closes
it. Ratchet: `test_portfolio_weights_are_deeply_immutable` (strict
xfail).

### RT-G027-7 — `gross_target` is decorative: no code path reconciles realized gross against it (NON-BLOCKING note)

`Portfolio(weights={"A": 5.0, "B": -5.0}, gross_target=1.0)` is accepted
and runs through the ledger with `PeriodRow.gross_exposure = 10.0`
against a declared target of 1.0 — no check at construction, none in
`run_accounting`. The G027 constructors always emit consistent books
(probed to 1e-12), and `PeriodRow` carries the realized exposure for
CI-047, but the CI-047 sentence "reconciles realized gross against it"
is currently performed by NOBODY. Assign the comparison explicitly
(engine warning, or a pinned G028 metric check) so it cannot fall
through the G027/G028/G035 seams.

### RT-G027-8 — 2× "one-way" rate-base collision with G034 (cross-goal seam flag, for the G029 adapter; complements verifier M-1..M-6)

G027 pins `traded_notional_one_way = ½·Σ|trade|` (CI-046) and its own
test model charges `rate × one_way`. G034's `Trade.notional` docstring
calls each trade's unsigned notional "one-way, per CI-046/CI-048", so
`LinearCost` summed over a period charges `rate × Σ|trade|` — i.e.
`rate × G027's two_way`, 2× the other reading of CI-048's sentence
"cost = rate × one-way traded notional". On the establishment period the
gap is maximal: G/2 vs G of actually-bought notional (probe B3: one-way
= 0.5 while 100% of NAV is bought). P4's "5 bp per dollar traded"
supports the per-trade (two-way) base; CI-048's sentence reads as the
half. The G027 hook is seam-safe by construction — it passes `trades`,
`one_way`, AND `two_way` with exact definitions — but the G029 adapter
must pin the rate base once, or every cost number is ambiguous by 2×
(CI-046's "classic 2× ambiguity", now live between two in-flight goals).
Same seam, borrow side: G034 expects per-mark `ShortPosition` rows
(mark-to-market accrual); the G027 hook exposes one post-trade
`short_notional` per period, so borrow on drifted shorts is not
expressible (= verifier M-3; convention is pinned in `CONVENTIONS`).
Keeper `test_establishment_on_non_neutral_start_is_gross_over_two` pins
the G027 side of the convention.

## Observations (no defect; for the registers)

- **O-1 (dividends auto-reinvest in-name):** on the CI-019 total-return
  basis the ex-date dividend compounds the POSITION (`V·(1+r)`), never
  cash — economically "dividend reinvested in the same security at the
  ex-date close" rather than a pay-date cash leg (probe A6: 1000 → 1050
  position, cash 0). Correct for total-return reconstruction; worth a
  register line since real-world gross exposure drifts differently.
- **O-2 (Level-1/Level-2 asymmetry on constant scores):** an all-equal
  score vector gives Level 2 a typed `DegenerateLegError` but gives
  Level 1 a silently-built, purely ALPHABETICAL book (the pinned
  `(score, security_id)` tie rule with 100% ties). Deterministic and
  order-invariant, but a dead model emits a tradable-looking portfolio
  with no warning at Level 1.
- **O-3 (execution timing is upstream):** the ledger fills at the
  rebalance date by construction (first mark strictly later); zero-delay
  vs t+1 semantics live entirely in WHICH returns the caller supplies
  (G023's execution-anchored windows, CI-012). No same-bar defense is
  possible or claimed here.
- **O-4 (empty books are legal):** `Portfolio({}, gross_target=0.0)`
  runs through the ledger as all-cash (used by probe D1). Reasonable —
  but note a signal blackout therefore books flat periods silently.
