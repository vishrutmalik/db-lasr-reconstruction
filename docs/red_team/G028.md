## Findings

### RT-G028-1 — negative recorded charges flow through as NEGATIVE cost/borrow drag: the reporting layer launders RT-G027-5 into fabricated alpha (NON-BLOCKING, ratcheted; must fix before any external/G034 cost feed goes live)

`cost_borrow_drag` and `portfolio_summary` divide the ledger's recorded
`cost`/`borrow` by `nav_start` with no sign check. The G027 engine
accepts negative charges (RT-G027-5, ratcheted upstream), so a
sign-buggy cost model produces a ledger the reporting layer converts
into a dashboard reading `annualized_cost_drag = -2.35` (costs ADDING
235%/yr), `annualized_borrow_drag = -1.17`, Sharpe 48 — silently.
Reproduction (probe A1): a `(-50, -25)`-per-period cost model on a
4-period, NAV-1000 fixture. The module docstring's promise ("refusal
over guess … never a silent zero, NaN, or shrunk denominator") does not
cover the sign of a drag, and a negative drag is the single easiest way
to fabricate alpha through this layer. Why non-blocking: only a
buggy/malicious CostModel produces the input (G034 validates rates
≥ 0), and the number is at least visibly negative rather than absorbed.
Fix direction: refuse (or loudly flag in a typed field) `cost < 0` or
`borrow < 0` in `cost_borrow_drag`/`portfolio_summary` — mirroring the
fix direction already ratcheted upstream.
Ratchet: `test_negative_recorded_charges_must_not_report_negative_drag`
(strict xfail; accepts refusal or non-negative-with-flag).

### RT-G028-2 — panel outcome identity is keyed on labels (`as_of` instant, `horizon_steps`), not on the outcome window: two refusal bypasses (NON-BLOCKING, ratcheted)

**(a) Near-duplicate `as_of` evades the dedup.** Duplicate detection
keys on the exact `(as_of, security_id)` datetime. Two schema-valid
predictions for the SAME (security, `target_start`, `target_end`)
outcome with `as_of` perturbed by one second land in two separate
cross-sections: `duplicate_policy="refuse"` does not refuse, and the
same outcome is counted twice in every pooled metric (probe B1: 3
outcomes → 6 observations, two IC "dates" one second apart).

**(b) Equal-steps families evade the mixed-horizon refusal.** The
RT-G026-2 guard compares `overlap.horizon_steps` only. Two target
families with equal steps but different window extents (e.g. H=1
month-end-close vs H=1 next-open) pool silently; one cross-section then
holds two distinct `target_end`s and the per-date IC correlates scores
against incommensurable outcomes, with the Newey-West lag choice keyed
to steps alone (probe B4).

Why non-blocking: one sanctioned run pins `as_of` to grid decision
instants and one target family per config — both shapes need hand-built
or cross-run-pooled PredictionSets. That is exactly what a G029/G032
aggregation layer might do, so the panel (the designated enforcement
point) should close it. Fix direction: key duplicate detection on
`(security_id, target_start, target_end)` and refuse per-date
`(target_start, target_end)` heterogeneity — one check closes both.
Ratchets: `test_same_outcome_window_different_as_of_must_be_refused`,
`test_mixed_family_equal_horizon_steps_must_be_refused` (strict xfail).

### RT-G028-3 — `ic_summary`'s `horizon_steps` is caller-supplied and untied to the panel: a one-argument t-stat inflation channel (NON-BLOCKING, ratcheted)

CI-052's overlap-robust standard error is only as honest as the
`horizon_steps` argument, and nothing ties it to the panel that
produced the series — `ScoringPanel` carries the true horizon, but
`ICSeries` drops it. Passing `horizon_steps=1` for an H=3 family sets
NW lags to 0; on a persistent (AR(0.9)-shaped) IC series this inflated
the t-stat 1.51× (12.4 vs 8.2, probe D2). Not a formula bug — the NW
kernel itself is correct and hand-pinned — but the API leaves the one
integrity-critical constant to the caller's honesty while holding the
truth two fields away. Fix direction: stamp `horizon_steps` into
`ICSeries` at `ic_series(panel, ...)` and refuse a contradicting
argument (or drop the argument entirely).
Ratchet: `test_ic_summary_cannot_understate_overlap_with_a_lied_horizon`
(strict xfail; accepts refusal or lags derived from the true horizon).

### RT-G028-4 — `tail_quantile` deviates from the pinned A-G028-06 order statistic at exact-integer α·n boundaries (NON-BLOCKING, ratcheted)

The documented convention is the order statistic at
`ceil(α·n) − 1`. For α values not representable in binary whose
rational product with n is an exact integer, IEEE rounding pushes the
float product just above the integer and `ceil` up one: 30 (α, n)
pairs with α ∈ {0.01..0.99}, n < 260 — including α=0.07/n=100,
α=0.14/n=50, α=0.28/n=25 — return the k+1-th order statistic instead
of the documented k-th (probe D1). The deviation is deterministic and
always in the LESS conservative direction for a lower tail (VaR/ES one
order statistic closer to zero), precisely at the "α edges / n·α
integer boundaries" a config is most likely to sit on. Fix direction:
compute the index with `math.ceil(Fraction(...))` or an
epsilon-snapped product.
Ratchet: `test_tail_quantile_integer_boundary_matches_documented_convention`
(strict xfail).

### RT-G028-5 — the A-003 banner's "structural" enforcement is open over pydantic escape hatches; `render_text`'s last line of defense is a strippable `assert` (NON-BLOCKING, ratcheted)

The validator holds on every VALIDATING path (construction, JSON
round-trip — both keeper-pinned). But `SyntheticProvenance.model_copy(
update={"banner": None})` and `model_construct(...)` are public pydantic
API and skip validation entirely; `ReportArtifact` accepts the tampered
instance (`revalidate_instances='never'`) and `to_json` serializes a
synthetic-flagged, banner-less artifact with no complaint (probe E2).
`render_text` guards with `assert artifact.provenance.banner is not
None` — an AssertionError (crash, not a typed refusal) in normal mode,
and under `python -O` the banner line renders `*** None ***`. Why
non-blocking: every honest constructor path is safe; the bypass
requires deliberately calling validation-skipping APIs or running -O.
Fix direction: re-validate provenance consistency inside `to_json` and
`render_text` (raise `MetricInputError`, never `assert`) — two lines,
closes construct/copy/-O at once.
Ratchet: `test_banner_stripped_via_model_copy_must_be_refused_at_serialization`
(strict xfail). Pass-side keeper:
`test_json_round_trip_banner_tamper_is_refused`.

### RT-G028-6 — `coverage_accounting` reconciles one direction only: universe members are explained, but predictions are never audited against the universe (NON-BLOCKING, ratcheted)

The N8 report classifies every UNIVERSE member per date — but nothing
checks the ledgers against the universe map: **(a)** a date carrying
predictions but absent from `universe_by_date` is simply not iterated;
the whole date escapes the audit and `fully_accounted` stays True
(probe F1). **(b)** a prediction for a security NOT in that date's
universe — universe contamination, the survivorship shape — is
silently discarded by the `members & predicted` intersection and never
surfaces anywhere (probe F2). A wrong or truncated universe table
therefore doesn't just weaken the report, it makes the honesty check
CERTIFY the dishonest denominator. Why non-blocking: the report is
strictly additive (nothing consumes `fully_accounted` yet) and the
sanctioned resolver produces consistent tables; the gap matters the
moment G029 wires the report into a gate. Fix direction: also
reconcile prediction/unscored/skip (date, id) pairs against the
universe map and surface both `dates_missing_from_universe` and
`out_of_universe` loudly.
Ratchets: `test_prediction_dates_absent_from_universe_map_must_surface`,
`test_out_of_universe_prediction_must_surface` (strict xfail; any fix
that surfaces the id/date or refuses flips them).

## Notes and observations (no ratchet)

- **N1 (latest_fit tie-break is lexicographic on `fold_id`):** the
  documented A-G028-01 tie rule resolves equal `model_fit_time` by max
  `fold_id` as a STRING. Sanctioned `fold_%04d` ids order correctly
  below 10 000 folds (keeper-pinned); foreign unpadded ids invert
  recency (`fold_2` beats `fold_10`, probe B2). Worth one register line
  on A-G028-01.
- **N2 (`oos_coverage` is only as honest as the caller's grid):**
  feeding the post-drop emitted grid yields `coverage_fraction = 1.0`
  with the N10 tail drop invisible. The G029 assembly MUST pass the
  planned rebalance grid (`BuildOutput.grid` / the clock's grid), never
  `emitted_grid`. Keeper pins both sides of the seam.
- **N3 (NW lag cap):** `lags > n-1` is silently capped (keeper-pinned);
  a 2-observation series accepts any horizon. Conservative direction is
  not guaranteed by the cap, only PSD is; acceptable, documented here.
- **N4 (bootstrap seed is caller-free but ledgered):** multi-seed
  shopping is API-easy (a loop), structurally unpinned; mitigations:
  the seed is a REQUIRED argument recorded in the result, and 300 seeds
  on null data produced 0 false CI rejections (percentile CIs are
  honestly wide). The experiment-config layer should pin the seed once
  (G029/G032).
- **N5 (`oos_coverage` accepts foreign-config fits):** no
  `config_hash` cross-check between `fits`, the claim, and the grid; a
  one-line equality check would close it (mirrors G026 note N6).
- **N6 (empty PredictionSet → `horizon_steps=1`):** a fabricated
  default on an empty panel; harmless today (every consumer refuses
  empty/short series) but a hidden default all the same.
- **N7 (refusal enforcement is per-call):** splitting duplicated folds
  across two PredictionSets builds two clean `refuse`-mode panels; and
  `ICSeries`/`ICSummary` carry no provenance binding to any panel, so
  hand-pooled series are unpoliced. Design note for G029: one panel per
  (config, family) per run, built once.
- **N8 (`sign_stability = 1.0` at a 0.0 point estimate):** documented
  in the docstring, still an odd dashboard value for "maximally
  sign-stable nothing".
- **N9 (UNMAPPED sentinel collision):** a group map may assign the
  literal `"UNMAPPED"` value; the mass joins the loud bucket while
  `unmapped_ids` lists only genuinely unmapped names — ids and mass no
  longer reconcile. Cannot hide anything (direction is toward MORE
  visible unmapped mass); refuse the reserved name in group maps when
  convenient.
- **N10 (magnitude-unbounded Sortino; `rf_per_period` default):** one
  −1e-9 period yields Sortino ≈ 1.6e8 as a plain float (honest math;
  the typed-None path triggers only at exactly zero downside). And
  `rf_per_period` defaults to 0.0 — consistent with the pinned zero
  cash yield (A-G027-05) but the PR body's "still a visible argument"
  overstates it; a register line on A-G028-04 suffices.
- **O-1 (annualization is safe from complex powers):** period returns
  < −100% cannot reach `portfolio_summary` — the accounting engine
  refuses non-positive NAV, so `Π(1+r) > 0` on every real ledger
  (probe A3).
