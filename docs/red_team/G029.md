Auditor: red-team agent (adversarial). Implementation audited:

## Verdict

**NO_BLOCKING_FINDINGS.**

The pipeline, run honestly, does not fabricate a strong or leaked result: PIT
universe/feature resolution, purge/embargo, return alignment, cost base and the
CI-045/048/NAV accounting identities all re-derive correctly and independently from the
persisted artifacts; determinism holds byte-for-byte across PYTHONHASHSEED, filesystem
order and absolute run-root; the L3 leg, bad universe/fractile keys and the
merger-successor seeds are typed refusals leaving no partial-but-blessed run; and all 10
ratchet flips are backed by genuine production-code fixes (none weakened).

Three **NON-BLOCKING** findings (ratcheted strict-xfail) concern the reproducibility
*tooling*, not the pipeline's honesty: the run manifest — the headline artifact — sits
outside the hash tree it defines (RT-G029-1); `verify_run` never binds a run directory to
its config identity (RT-G029-2); duplicate YAML keys are silently last-wins (RT-G029-3).
These require external artifact tampering / directory misfiling / a malformed config to
matter; the pipeline itself computes honest artifacts.

## Attack log by surface

### Surface 1 — ratchet-flip integrity (highest priority)

See the table above. Two special-scrutiny items:

- **RT-G028-1 (can a negative charge reach drag metrics via ANY path?):** all three
  compute paths refuse — the accounting engine (`run_accounting`), the cost adapter
  (`LedgerCostAdapter.period_charges`), and the reporting layer (`cost_borrow_drag` /
  `portfolio_summary`) via direct-dataclass poisoning. The flipped keeper exercises the
  engine-refusal AND the direct-construction bypass. Residual (N-2): `verify_run` re-
  asserts the CI-045/048/NAV *arithmetic* identities but NOT the RT-G027-5 *sign* guard,
  so a hand-crafted, arithmetically-consistent `ledger.json` carrying negative cost (with
  a compensating `net_pnl`) passes `verify_run`. This is the same root cause as RT-G029-1
  (persisted re-assertion covers identities, not semantic guards); the report layer still
  refuses it downstream. Non-blocking.
- **RT-G035-3 (guard edge cases):** `T=N`/`δ=0`/collinear all refuse (`RiskModelInputError`).
  The guard is a numerical-rank threshold `min_eig <= n·eps·max_eig`. A covariance whose
  smallest eigenvalue is JUST above that cutoff (two names collinear to ~1e-8, δ=0) passes
  and yields a gross-2.0 book at predicted vol 1.4e-8 under a 1bp cap — a residual of the
  vacuous-vol family (N-1). **Not a weakening of the flip** (the flip refuses the exact
  ratcheted δ=0 shape) and **unreachable in G029** (L3 is a typed refusal); recorded for
  the G038 L3 owner.

### Surface 2 — reproducibility theater

- **(a) Tamper each artifact class.** All 8 HASH-LISTED artifacts (predictions, ledger,
  report.json, report.txt, quality_report, feature_values, cost_ledger, fold_ledger) are
  tamper-evident — one trailing byte on any of them is CAUGHT by `verify_run`. Keeper:
  `test_every_hashed_artifact_is_tamper_evident`.
  - **MISS (RT-G029-1):** `manifest.json` — which holds `passed`, the A-003
    `synthetic_banner`, `suspected_leaks`, `counts`, `leakage_audit`, `acceptance` — is the
    ONE artifact NOT in the hash tree. `verify_run` re-hashes the 8 files against
    `manifest["artifacts"]` but never hashes or re-derives the manifest's own claims.
    Editing `synthetic_banner→null`, `passed→true`, `suspected_leaks→[]` still verifies
    CLEAN while contradicting the (hashed, unchanged) `report.json`. The idempotent rerun
    then returns this poisoned manifest verbatim, and the CLI prints `passed: True` with NO
    banner — an A-003 banner strip through the rerun path. Deleting an artifact AND its
    `manifest["artifacts"]` entry is likewise undetected (the artifacts list is self-
    defined). The PR body's "persisted-identity re-assertion" overstates the tool: it
    re-asserts the ledger's numerical identities, not the run identity.
- **(b) hash16 collision/reuse.** `run_id = "run-" + sha256(identity)[:16]` (64-bit
  truncation). A collision needs ~2^32 runs (birthday) — not a practical finding. But
  REUSE without a collision IS reachable → **RT-G029-2:** a valid run dir for config A,
  dropped at the deterministic `runs/run-<B_hash16>/` path, is accepted by
  `run_experiment(B)` as an idempotent no-op — `verify_run` passes (A's artifacts are
  internally consistent) and B silently returns A's manifest (A's `config_hash`,
  `experiment_id`, `passed`). `verify_run` never checks `manifest["config_hash"]` against
  the directory name. Verified live: run B (`run-97b89d…`) returned run A's manifest
  (`experiment_id: rt_repro_a`).
- **(c) idempotent-rerun cache poisoning.** A partial/mismatched run dir is caught: the
  rerun calls `verify_run` first and raises `PipelineError` on any hash mismatch, so a
  corrupted artifact blocks the no-op. The gap is only the manifest itself (RT-G029-1) and
  cross-config substitution (RT-G029-2). Clean partial poisoning (missing file present in
  `manifest["artifacts"]`) IS caught ("missing artifact").
- **(d) hidden nondeterminism.** Byte-identical artifact trees across `PYTHONHASHSEED ∈
  {0,1,2,unset}`, across shuffled input creation, and across different absolute run roots
  (the e2e `test_ci042_double_run_byte_identity` compares every file including
  `manifest.json`). No absolute path leaks into any artifact (`grep` for `/Users`,
  `/private/tmp`, root name over the full run dir → clean). Run identity excludes
  `artifacts_root` by construction (`_run_config_hash`). **No finding.**

### Surface 3 — composition leaks the units couldn't see

- **(a) N8 stamp binding.** Feature stamps are batch properties (PK excludes
  `knowledge_time`; persisted that way — `feature_stage.py`, `experiment._persist`). The
  runner enforces `train_max_knowledge_time <= fit_time` and `train_max_target_end <=
  fit_time` (CI-006/010/015a). Feature values are PIT-gated via `FeatureEngine(registry,
  pit)` at each decision instant, so `feature_knowledge <= as_of <= target_end = record
  knowledge`; the record-knowledge check dominates. No fit sees a feature batch stamped
  after its instant. **No finding.**
- **(b) purge/embargo through the REAL config surface.** `generate_folds` runs with
  `purge="required"`, `overlap_mode=family.overlap_mode`,
  `embargo_horizons=family.embargo_horizons`. RT-G026-1's `close_to_open` shape stays
  ratcheted upstream (the `1M`/`month_end` family is `pooled_as_paper`, symmetric close-
  to-close; `close_to_open` is not selectable through this config). **No finding.**
- **(c) adapter under composition.** Costs computed on the accounting engine's per-period
  trade deltas; rate base independently reconciled as `0.002 × two_way × nav_start` over
  22 periods (0 mismatches) — per dollar traded, NOT `rate × one-way` (RT-G027-8 pin holds
  end to end). Delisting-week terminations flow through `MarkStep.terminated`; the tail
  fold's incomplete window is a typed `FoldSkip` (`zero_test_rows`), never a silent
  partial. **No finding.**
- **(d) end-of-history.** `build_scoring_panel(data_end=build_as_of)` excludes
  `target_end > data_end` (CI-052); the last walk-forward fold whose test range holds no
  realized decision date is ledgered as `FoldSkipReason.ZERO_TEST_ROWS` (>=1 in the e2e
  run). No incomplete target window enters a metric. **No finding.**
- **Interval-vintage merge (A-G029-02, disclosed).** `_merge_interval_vintages` collapses
  open+closure vintages to the final shape stamped at the OPEN instant, REFUSING when the
  closure was published after the interval end (LT-016 shape). Verified PIT-sound for the
  pipeline's actual queries: `PitStore.universe` gates by `knowledge_time <= as_of` AND
  interval containment `valid_from <= day <= valid_to`, so the early-visible `valid_to`
  only excludes a name once `as_of` is past it — by which point the guard guarantees the
  exit was published. The "direct `valid_to` reads remain leak-prone" caveat is real but
  not exercised by the resolver path; already flagged as found-not-fixed #2 (schema owner).
  **No finding at the G029 pipeline; disclosed limitation.**

### Surface 4 — CLI / config attacks

- Unknown experiment key (top-level and nested `pipeline.*`) → `ValidationError`
  (`extra="forbid"` composes). Keeper: `test_unknown_experiment_key_is_refused_not_dropped`.
- `portfolio_level=3` → typed `PipelineConfigError` naming G038, no run dir written
  (keeper: `test_portfolio_level_3_is_a_typed_refusal_with_no_partial_run`). `_build_book`

- Bad `fractile_key` ("mars"), bogus `universe_instance` → typed `PipelineConfigError`.
- Banner integrity on a FRESH run: the A-003 banner is the first stdout line and the first
  line of `report.txt` (both hashed via report.json/txt). The only strip is the tampered-
  rerun path (RT-G029-1).
- **MISS (RT-G029-3):** duplicate YAML mapping keys are silently last-wins
  (`yaml.safe_load`): a config with two `seed:` leaves loads as the SECOND value (1729 →
  7) with no error/warning. Keepers: the strict-xfail refusal ratchet + a teeth test
  pinning the live `seed == 7` behavior.

### Surface 5 — merger-successor honesty

Seeds 2/3/5/7/11/13/42/123 trip `build_corporate_actions`' cross-exchange successor seam
→ `IdentityError` (a `ValueError`/`LasrError` subclass). Verified: the refusal is raised
BEFORE `_persist`, so no partial run directory is left behind (keeper:
`test_merger_successor_seed_is_a_typed_refusal_no_partial_run` asserts `runs == []`). The
CLI cannot swallow it into a blessed run. This is a pre-existing canonical-builder issue
(found-not-fixed #1, out of the G029 lane); G029 handles it honestly.

### Surface 6 — ci.yml paths-ignore / rename

`paths-ignore` lists `coordination/**`, `docs/**`, `*.md` on both `pull_request` and
`push`. GitHub evaluates the filter against the PR's changed-file set (base…head). A rename
is represented as delete-old + add-new; both paths appear, so a rename that touches any
non-ignored path (e.g. into `src/`) still triggers CI. There is no way to modify a
non-ignored path without it appearing in the changed set → no docs-only-skip smuggling of
code. The e2e-smoke and determinism jobs are now ACTIVE (ubuntu-only, `-k` split so the
determinism class isn't double-run), `test-macos` stays push-only. **No finding.**

### NON-BLOCKING (ratcheted strict-xfail in `tests/leakage/test_red_team_g029_slice_attacks.py`)

- **RT-G029-1** — the run manifest (headline artifact: `passed`, A-003 banner,
  `suspected_leaks`, counts, leakage_audit, acceptance) is outside the hash tree it
  defines; `verify_run` neither hashes nor re-derives it against the hashed evidence, so a
  manifest edited to null the banner and flip `passed` verifies clean and is re-emitted by
  the idempotent rerun (A-003 strip). Fix direction: hash the manifest's identity/verdict
  block into a self-consistent anchor, or have `verify_run` re-derive `passed` /
  `synthetic_banner` from the hashed `report.json`/`ledger.json` and cross-check.
  Reproduce: `pytest tests/leakage/test_red_team_g029_slice_attacks.py::test_rt_g029_1_manifest_edits_are_caught_by_verify_run`
  (XFAIL today; XPASS on fix).
- **RT-G029-2** — `verify_run` never binds a run dir to its config identity, so a valid
  run dir misfiled at another config's deterministic `run-<hash16>` path is blessed as
  that config's result. Fix direction: `verify_run` should recompute-or-cross-check that
  the directory name equals `run-` + `manifest["config_hash"][:16]`, and the idempotent
  rerun should confirm `manifest["config_hash"] == resolved_hash` before returning the
  existing run. Reproduce:
  `pytest tests/leakage/test_red_team_g029_slice_attacks.py::test_rt_g029_2_cross_config_cache_substitution_is_refused`.
- **RT-G029-3** — duplicate YAML mapping keys are silently last-wins in
  `load_yaml_mapping` (`yaml.safe_load`). Fix direction: a duplicate-key-rejecting loader
  (custom `SafeLoader.construct_mapping` with a seen-key check) → `ConfigLoadError`.
  Reproduce:
  `pytest "tests/leakage/test_red_team_g029_slice_attacks.py::test_rt_g029_3_duplicate_yaml_keys_are_refused"`.

### Notes (observations, not defects; for owners)

- **N-1 (G038):** the RT-G035-3 rank guard is a hard eigenvalue threshold; a near-singular
  (cond ~1e8) but nominally-PD covariance passes and produces a book whose predicted vol
  sits far below the vol cap — a cap that isn't binding is vacuous risk control. A cap-
  utilization / condition-number warning would close the residual. Unreachable in G029
  (L3 refused); for the G038 L3 leg.
- **N-2 (G029/schema):** `verify_run` re-asserts CI-045/048/NAV but not the RT-G027-5 sign
  guard on the persisted ledger; a hand-crafted arithmetically-consistent negative-cost
  `ledger.json` passes it (same root cause as RT-G029-1). Downstream reporting still
  refuses it.
- **N-3 (observation):** run-level feature eligibility drops a factor for the WHOLE run if
  it is ineligible at ANY date (`feature_stage`) — a fixed-dimension-ensemble engineering
  choice that uses full-window eligibility (not values/targets), so it cannot leak target
  information; documented and conservative (tends to remove factors), not a
  performance-inflating leak.
- **N-4 (disclosed):** interval-table vintage gap (A-G029-02) — PIT-sound for the
  resolver's containment queries; direct `valid_to` reads remain a schema-owner follow-up
  (found-not-fixed #2).
