## BLOCKING findings

### RT-G034-1 — `breakeven_one_way_bps` overstates the break-even cost 2×
**Where:** `src/lasr/costs/breakeven.py` (docstring convention + closed form).

**Mechanism.** The module defines per-period drag as
`r * turnover_t` with `turnover_t` explicitly pinned to the **CI-046
one-way** convention (= ½·Σ|Δw|, "half the sum of absolute weight
changes"). But the sibling `CostModel` charges `rate × |signed_notional|`
on **every** trade — both legs of a rebalance — i.e. `rate × Σ|Δw|·NAV =
rate × 2 × one-way-turnover × NAV`. That per-dollar-traded semantics is the
papers' (E-P4-25: "5 bp **per dollar traded**"; P1/P2/P3 one-way rates are
per-side charges) and is what any G029 backtest will actually deduct. The
break-even therefore zeroes HALF the real drag: the reported survivable
cost is exactly **2× too high**. CI-046 itself names "the classic 2×
turnover ambiguity corrupting cost drag" as the thing it exists to prevent.

**Evidence (probe 1, reproduced in the keeper).** NAV 100; one period;
sell 50 A / buy 50 B (one-way turnover 0.5); gross 1%:

```
module break-even          : 200.0 bps
CostModel charge at be     : 2.0000  (currency, NAV=100)
net at claimed break-even  : -1.0000 (should be 0.0)
true break-even (per-dollar-traded, = CostModel semantics): 100.0 bps -> net +0.0000
overstatement factor       : 2.000x
```

**Impact.** MP §25 requires break-even costs in every backtest report; P1's
cost-grid framing (P1-38) is consumed through this number. As shipped, any
strategy whose true break-even is at or below the evidenced cost level
(e.g. true 20 bps under `p2_flat_20`) would be reported as surviving up to
2× that — viability fabricated by arithmetic, silently.

**Fix direction (one-line semantics choice, implementer's call):** either
`rate = Σgross / (2·Σ one_way_turnover)`, or redefine the input as the
two-way traded-notional fraction and rename/redocument — then reconcile by
test against `CostModel.run` on an equivalent trade list (the keeper's
xfail flips to a permanent regression when fixed). The implementer's own
hand tests (`test_hand_value_200_bps` etc.) encode the halved convention
and will need the same correction. CI-048's phrase "cost_t = rate ×
one-way traded notional" should be clarified at the same time: read as
"per-side traded notional, i.e. Σ|Δw|·NAV" it matches `CostModel`; read as
"= one-way turnover × NAV" it would instead indict `CostModel` — the paper
language ("per dollar traded") settles it in `CostModel`'s favor.

**Reproduce:**
`uv run pytest tests/leakage/test_red_team_g034_cost_attacks.py -k rt1 -rxX`
(strict xfail + independent-recompute teeth test).

## Non-blocking findings (ratcheted — strict xfail until fixed)

### RT-G034-2 — participation cap and convex impact evaded by trade splitting
Duplicate `(security, date)` rows are priced independently, so the P2/P3
capacity surface flags per ROW: 2M traded against a 1M cap raises the
`adv_participation_exceeded` flag as one row but **no flag at all** as
4×500k rows (probe 2a); a same-day buy 0.9M + sell 0.9M pair (1.8M total
volume vs 1M cap) is also silent (probe 2a′). The convex impact component
shrinks under the same slicing: 2 rows → 1/√2 of the single-row charge,
10 rows → 0.316× (probe 2b). Linear/commission/spread are split-invariant
or over-charge, so per-row charging is correct for them — the defect is
confined to the two components whose economics are functions of TOTAL
daily traded notional per name. Any G027 ledger with partial fills or
two-leg same-day trades will silently under-report capacity breaches
(E-P2-24/26, P3-31) and under-charge M-13 impact. Fix: aggregate
per `(security, date)` before participation/impact, or refuse duplicate
keys, or pin a one-row-per-(security,date) contract on the G029 adapter.
Keepers: `test_rt2_*` (1 xfail ratchet + 2 held pins).

### RT-G034-3 — version bridge silently drops configured regional borrow and banners it as evidenced
`stack_from_version_config` builds `borrow=None` whenever the BASE
`borrow_bps_pa` is 0/None — **discarding a non-empty
`borrow_bps_pa_region_override`** (probe 5c: configured 100 bp p.a. for
"emerging"; a 1M short held 365d accrued 0.00 instead of 10,000) — and
stamps the stack `zero_borrow_assumption="zero borrow per version spec"`,
so the run banners the deletion as an evidenced assumption. No shipped
version spec hits this edge (P4 has base 50/100), but the failure is
silent cost deletion plus a false provenance claim. Fix: refuse the
contradictory section, or build a borrow component with base 0 + the
overrides. Keeper: `test_rt3_bridge_must_not_silently_drop_regional_borrow`
(xfail; accepts either fix).

### RT-G034-4 — registered presets are mutable in place through dict fields
`PRESETS` is a read-only mapping and the models are pydantic-frozen, but
dict-typed FIELDS (`LinearCostConfig.region_overrides`,
`BorrowFeeConfig.region_overrides`, `CostStackConfig.region_multipliers`)
are plain mutable dicts. Probe 4:
`PRESETS["p3_tiers"].stack.linear.region_overrides["latam"] = Param(0.01…)`
succeeds and re-rates LATAM from 5,000.00 to 1.00 per 1M — for every
subsequent caller AND for models built before the mutation (the config is
held by reference). "Presets are frozen data" is therefore only
attribute-deep. `grid_variants` output does not share the dict (pydantic
re-validation copies it), which contains the blast radius to the registry
itself. Fix: freeze mappings at construction (e.g. `MappingProxyType` via
validator) or deep-freeze the config models. Keeper:
`test_rt4_registered_preset_dict_fields_are_immutable` (xfail, restores
the evidence value in `finally`) + a pristine-rate guard pin.

### RT-G034-5 — non-finite charges flow through totals and `net_of` silently
Charges are never finiteness-checked. With all INPUTS individually valid:
`coefficient_bps=0` (legal, ≥0) + overflowing participation
(1e155 notional / 1e-155 ADV) yields `0 × inf = NaN` → `totals.total =
NaN`, `net_of(...) = NaN`, no refusal, no flag — the skill's "costs ≥ 0
always" invariant broken silently (probe 8b). `coefficient_bps>0` gives
`+inf` → `net_of` = −inf (probe 8a). `exponent=2.0` with participation 1e200
raises a raw `OverflowError` — loud but untyped, violating the MP §26
typed-error rule (probe 8c′). Realistic magnitudes cannot trigger this and
faithful presets never enable impact (A-G034-03), hence non-blocking. Fix:
validate `ComponentCharge.amount` finite-and-≥0 (typed refusal). Keeper:
`test_rt5_charges_are_finite_or_refused_loudly` (xfail).

## Non-blocking notes (no ratchet; executable pins where noted)

- **N1 — borrow default invites a 28.5% undercount.**
  `ShortPosition.accrual_days` defaults to 1 "calendar day". A short held
  all of 2015 and marked business-daily with the default accrues
  3,575.34 vs 5,000.00 true (261/365) — no warning, nothing to see in the
  output (probe 3a). The model is exact w.r.t. covered days; the CALENDAR
  is entirely the caller's job (A-G034-05) and the default silently picks
  the undercounting choice for any caller that marks less often than
  daily (weekly marks with the default would undercount 7×). This sits on
  the evidenced P4 path once G029 wires real ledgers. Recommendation:
  remove the default (require explicit accrual_days) or add a
  calendar-coverage reconciliation (Σ accrual_days vs date-span) to the
  G029 adapter contract. Pinned executable:
  `test_n1_borrow_exact_in_covered_days_but_daily_default_undercovers`.
- **N2 — partial free shorting via per-security override is silent.**
  `borrow_fee_bps_pa_override=0.0` on a fee>0 stack accrues zero with no
  banner (total borrow stays >0) and no per-accrual flag: 99M of a 100M
  short book borrowed free left only the 1M leg charged (probe 6b). The
  override is legitimate caller data (M-12 borrow_daily), but a zero-fee
  accrual on a charging stack deserves a flag so reports can total
  "free-borrow notional". Pinned executable: `test_n2_*`.
- **N3 — banner and HTB "forbid" tripwire guard only `run()`.**
  `price_trades()`/`accrue_borrow()` are protocol-sanctioned entry points;
  neither computes the zero-borrow banner nor enforces
  `hard_to_borrow_policy="forbid"` — a forbidden name accrues normally,
  flag-only, via `accrue_borrow` on the very stack whose `run()` raises
  (probes 6c/6d). All 8 presets ship policy "flag" (documented as the
  structural default; exclusion belongs before optimization per skill §4).
  G029 must route full-run pricing through `run()` and treat the two
  protocol methods as internals. Pinned executable: `test_n3_*`. (Adjacent
  to the verifier's note 6, which covers the HTB-exclusion deferral; this
  note is about the tripwire's bypassable surface.)
- **N4 — bridge accepts off-grid and contradictory rates silently.**
  `base_bps=1` (or 0) against a declared `scenario_grid_bps=[5..30]` is
  accepted with no grid-membership guard (probe 5a; free trading at 0 has
  no banner analogue); when BOTH `base_bps` and `one_way_bps` are set,
  `base_bps` wins with no consistency check (probe 5b: 20 configured, 5
  charged). There is also no runtime binding of preset→version
  (`PRESETS["p4_base"]` prices an `nlasr_2012` backtest without complaint
  — probe 5d); today the link is only the static
  `test_version_ids_match_version_specs`. Recommendation: a section-level
  guard (guards.py has none for costs) + a `(VersionSpec, CostScenario)`
  binding check in G029. Pinned executable: `test_n4_*`.
- **N5 — reports cannot distinguish "component not modelled" from
  "component = 0".** `CostRunResult` carries no record of the enabled
  component stack; a disabled half-spread with spread data present charges
  nothing, indistinguishable in the output from a zero spread (probe 9c).
  Presence-is-enabled is a clean config rule (MP §26), but MP §25 report
  sections should state the active stack; recommend echoing the stack (or
  a component manifest) into `CostRunResult` for the G036 report layer.

## Observations (attacked and held)

- **Break-even degenerates:** zero total turnover → typed refusal (not an
  infinite/zero break-even); negative gross → negative break-even returned
  un-clamped (honest); per-period zero-turnover entries fine.
- **Sign/dust/zero conventions:** sells charged exactly like buys (abs);
  0.0001-notional dust charged proportionally (no round-to-zero);
  zero-notional = "no trade" charges 0 including commission (documented
  convention; keeps monotonicity from 0).
- **Reporting split (probe 7):** per-trade bucket fields sum to
  `TradeCost.total` and per-period `net_of` residual is EXACTLY zero by
  construction; whole-run totals vs `fsum` recompute and vs Σ period rows
  agree to ≤9e-16 relative on a 200-trade, 60-mark adversarial ledger
  spanning 12 orders of magnitude with commission+spread+linear+impact+
  participation+borrow+region-multiplier+size-scaling all enabled. The
  region multiplier and size-scaling hook multiply the DECOMPOSITION
  consistently (each bucket scaled; totals remain the bucket sum — probe
  7v). Association-order ulp effects are the verifier's non-blocking 1/5;
  not re-filed.
- **Composition order (A-G034-01) vs evidence (probe 9):** `p3_tiers`
  reproduces the paper's ALL-IN per-trade bps exactly (20/30/40/50 bps →
  total == linear bucket, all other buckets zero), so the pinned
  additive-independent composition is FAITHFUL for every shipped preset
  (single linear component — the two readings coincide, as the A-G034-01
  note claims). For linear modifiers, additive-then-multiplicative ==
  multiplicative-then-additive identically (distributivity — probe 7v), so
  the assigned "material understatement" case does not exist in the
  shipped composition. The only divergent reading is multiplying NOTIONAL
  instead of charges before convex impact: the module's charge-multiplier
  understates that alternative by participation^exponent (1/√2 at ×2,
  exponent 0.5 — probe 9b). That is optimistic ONLY if a region multiplier
  or the size-scaling hook were ever used to proxy "trading N× the
  notional" — which A-G034-04 explicitly does not claim (capacity is
  ADV-cap + fixed-AUM sims per P3-31; presets keep both hooks off). Judged
  consistent with evidence; flagged in the A-G034-04 register context as a
  must-not-repurpose.
- **Borrow conventions:** leap-year ACT/365 charges 366/365 of the annual
  fee (correct convention); `accrual_days=0` refused at the type level so
  a marked 1-day short cannot accrue 0 days; a short opened and closed
  BEFORE the period mark produces no mark and is invisible to this module
  (G027 ledger contract, with N1's reconciliation as the guard);
  zero-notional marks accrue 0; borrow-free stacks emit explicit
  zero-amount accrual records (nothing vanishes).
- **Banner matrix on `run()` (probe 6a):** shorts+tagged-zero-borrow →
  banner with tag text/prov/src; no shorts → none; shorts+borrow charged →
  none; fee>0 stack whose overrides resolve every mark to zero → untagged
  banner (handled). Untagged borrow-free stack un-constructible
  (config error); contradictory tag on a charging stack refused.
- **Impact near-zero ADV:** `adv_notional=0` on enabled impact is a typed
  refusal; tiny-but-positive ADV blows the charge up monotonically and
  finitely at realistic magnitudes; no silent cap (RT-G034-5 covers only
  the overflow extreme).
- **Currency:** notionals are unit-less "portfolio base currency" by
  convention; `net_of` cannot detect a caller mixing units (returns vs
  currency) — CI-048 currency-space reconciliation is a G027/G029
  obligation already flagged in the module docstring; no new defect.
- **Determinism:** double runs bit-identical (implementer property test
  re-run; no RNG/clock found in the module).

### NON-BLOCKING (ratcheted — strict xfail keepers appended)

- **RT-G034-6 — size-scaling pow overflow escapes as a raw untyped
  `OverflowError`.** `CostModel._size_multiplier` calls
  `math.pow(aum/reference_aum, exponent)` with no guard: finite,

  classification as round-1 RT-G034-5. Loud crash, never silent
  under-charging. Keeper:
  `test_rt6_size_scaling_pow_overflow_must_be_typed` (xfail strict,

  finiteness-guarded.** Inputs are validated finite but the OUTPUT is
