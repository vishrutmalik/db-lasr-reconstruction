## Verdict

**NO_BLOCKING_FINDINGS.** The optimizer core survived every attack aimed
at fabricating a blessed-but-illegal book on the shipped path: gross and
net equalities are independently re-verified and never off by more than
float noise; the wash detector fires on single-name, all-zero, and
cost-dominated gross-equality configs; `upper_bound` mode is genuinely
wash-free (a cost-dominated book collapses to empty, not to fake
leverage); the estimated linear cost reconciles EXACTLY (rel ≤ 1e-9)
with the merged G034 `CostModel` on an adversarial asymmetric-leg
rebalance including a forced close; the effect-separation additivity
identity is exact (residual 0.0) across every feasible alpha scale;
negative cost/borrow rates are refused at config; and the book is
bit-identical across input order and PYTHONHASHSEED ∈ {0, 42, 31337}.

**4 non-blocking defects ratcheted as strict xfail** (RT-G035-1..4),
**3 non-blocking notes** (N-1..N-3), and recorded observations. All four
ratchets sit on contract edges no *evidenced* config is shown to reach;
each must be fixed before the edge becomes reachable (per-finding
riders). None fabricates a strong performance number on the shipped
path, so the strong-results protocol was not triggered.

## Non-blocking findings (ratcheted — strict xfail until fixed)

### RT-G035-1 — forced-close ADV breaches are blessed inside an ABSOLUTE weight-unit tolerance, and forced closes are absent from the post-solve verification

**Where:** `level3_optimizer.py` `_prepare` (pre-solve forced-close ADV
check, lines ~308-327) + `_final_checks` (the `adv_participation` report
row covers optimized names only, line ~554).

**Mechanism.** The forced-close ADV check is
`abs(exit_weight) > cap + config.solver.constraint_tolerance` where
`cap = adv_notional * participation / nav` in WEIGHT units and
`constraint_tolerance = 1e-6` is ABSOLUTE. The cap scales with `1/nav`;
the tolerance does not. The PR's claimed "independent post-solve
verification of every constraint" never revisits forced closes — the
`adv_participation` report row is `max(|w − w_prev| − t_upper)` over the
OPTIMIZED ids only, so a universe-exiting name's breach is invisible in
`constraint_reports` too.

**Evidence (probe 1a/1b, keeper
`test_forced_close_participation_must_honor_the_cap`).**
- nav 1e9, ADV 1e5, cap 5%: a forced close trading $5,900 = **5.9% of
  ADV, 1.18x the cap** builds with no error and no report row.
- nav 1e12, ADV 1e4: a forced close trading $900,000 — **90x the entire
  ADV, 1800x the cap** — is blessed (cap weight 5e-10 vs tolerance 1e-6).
- Teeth held (`test_exit_beyond_tolerance_is_a_named_conflict`): an exit
  beyond `cap + tol` raises the typed named conflict, so the pre-solve
  check does fire — the defect is purely the un-scaled band.

**Why non-blocking:** the trade notional the breach can reach is bounded
by `tolerance * nav`, so a material currency breach needs both a very
large NAV and a universe-exit name whose ADV has collapsed below
`~tolerance/participation` of NAV — a real but narrow conjunction; and
the breach is a participation-limit slip (execution realism), not a P&L
fabrication. Fix direction: make the forced-close ADV tolerance relative
to the cap (or express the check in currency units), and include forced
closes in `_final_checks` / `constraint_reports` so the post-solve
verification genuinely covers "every constraint … forced closes
included" as the PR claims.

### RT-G035-2 — A-004 manifest forgery: the optimizer trusts `is_substitute` but copies `manifest` with no cross-check (= verifier NB-1, sharpened)

**Where:** `level3_optimizer.py` `_prepare` (the only risk-model gate is
`if not risk_model.is_substitute`, line ~335) + result assembly
(`risk_model_manifest=risk_model.manifest`, line ~968).

**Mechanism.** `_prepare` checks ONLY `risk_model.is_substitute`; the
manifest copied verbatim onto `Level3Result` (and, downstream, onto
every decomposition stage / report per the A-004 banner discipline) is
never checked for internal consistency. A hostile `RiskModel` with
`is_substitute=True` and `RiskModelManifest(name="axioma_v4_replica",
substitute=False, assumption_id=None, shrinkage_intensity=None, …)`
passes every gate: `substitute=False` skips the manifest's
`__post_init__` A-004 requirement, and `shrinkage_intensity=None` skips
`_prepare`'s intensity cross-check (`if delta is not None`). This is the
G020-B4 / RT-G028-5 banner-stripping shape the three-layer labelling
claims to prevent, reached through the interface's own seam.

**Evidence (probe 2a, keeper
`test_is_substitute_manifest_mismatch_must_refuse` +
`test_forgery_currently_strips_the_label`).** A vol-capped
(risk-bearing, predicted vol 0.098) book builds whose
`result.risk_model_manifest.substitute is False` — an A-004 substitute
result presenting as the proprietary model.

**Why non-blocking:** it requires a HOSTILE `RiskModel` implementation;
the shipped `ShrinkageRiskModel` always reports `is_substitute=True` and
a matching `substitute=True` manifest, so no shipped path is affected —
same class as RT-G027-6 (shallow-freeze) and the G020-B4 precedent. Fix
direction: `_prepare` must refuse `risk_model.is_substitute !=
risk_model.manifest.substitute`, and should require a non-None
`shrinkage_intensity` when `config.risk_model.kind ==
"shrinkage_substitute"`.

### RT-G035-3 — rank-deficient / zero-variance shrinkage covariance defeats the `target_volatility` cap via the null space, while REPORTING the cap satisfied

**Where:** `level3_risk.py` (no rank / minimum-eigenvalue guard;
A-G035-01 claims only PSD, which is true but ≠ positive-definite) +
`level3_optimizer.py` (the vol cap `vol_fun` and the risk penalty trust
`sigma` blindly; alpha maximization ACTIVELY seeks the null space).

**Evidence (probe 2c/2d, keeper
`test_zero_variance_names_must_not_pass_a_tight_vol_cap` +
`test_singular_covariance_currently_builds_a_levered_book`).**
- Two constant-return names (sample variance exactly 0 — a legal panel):
  the optimizer builds `{Z1: +1.0, Z2: −1.0}` — 2.0 gross, expected
  alpha 0.10 — with `predicted_volatility == 0.0`, blessed under a
  **1 bp** annualized vol cap.
- `shrinkage_intensity=0` (legal: A-G035-01 "0 = sample") with T=3 < N=4
  collinear histories: covariance eigenvalues
  `[−1.3e-19, −8.2e-37, 6.4e-20, 4.0e-3]` (PSD only to float noise); the
  optimizer loads the null space for a 2.0-gross book at predicted vol
  == the 1 bp cap.

**Why non-blocking:** the predicted vol is INTERNALLY consistent with
the (degenerate) estimator, and the substitute is labelled — the
dishonesty is that a rank-deficient estimate makes "0 vol" vacuous, not
that a number is mislabelled. No evidenced G035/P4 config is shown to
run `delta=0` with `T ≤ N`. BUT the realistic shape is exactly that:
`delta=0` (the natural "use the sample covariance" choice) on a large
universe with limited history (hundreds of names, ~60 monthly obs) makes
the sample covariance singular with an enormous null space, so any vol
cap / `risk_aversion` penalty is silently unenforceable while reporting
enforcement. **Must fix before any L3 run uses `delta=0` on `T ≤ N`
histories:** refuse (or warn loudly) when a vol cap / `risk_aversion`
consumes a covariance with `n_observations ≤ n_securities` at
`delta=0`, or floor the minimum eigenvalue, or refuse zero-variance
names.

### RT-G035-4 — `decompose_effects` never reconciles the L1/L2 spec gross against the L3 config gross; a leverage difference is booked as `optimization_effect`

**Where:** `level3_compare.py` `decompose_effects` — `l1_spec`,
`l2_spec`, and `l3_config` are independent inputs; only the three L3
toggles are derived from `l3_config` (so THEY share gross). The docstring
claims "every stage shares identical base constraints," but that holds
only among the L3 stages.

**Evidence (probe 3b, keeper
`test_gross_mismatch_between_stages_must_refuse` +
`test_leverage_mismatch_currently_inflates_optimization_effect`).**
Running L1/L2 at `gross_exposure=2.0` while `l3_config` runs
`gross_target=4.0`: the L3 stage's book is gross 4.0 vs the L1/L2 books'
gross 2.0, and `optimization_effect` jumps from +0.008 (matched) to
+0.068 (mismatched) — an 8.5x inflation attributed to optimizer skill,
with no refusal or warning.

**Why non-blocking:** the additivity identity still holds (the effect is
mislabelled, not lost), and a coordinated caller passes a consistent
gross. But the MP §24 "Separate:" decomposition exists precisely to
attribute value correctly, and this silently credits leverage to
construction skill. Fix direction: refuse (or warn) when the L1/L2 spec
gross does not equal `l3_config.constraints.gross_target`.

## Non-blocking notes (no ratchet)

- **N-1 (config instance-injection of a false A-004 acknowledgment,
  probe 2b):** `RiskModelConfig.model_construct(substitute=False, …)` is
  accepted by `Level3Config` (pydantic v2 `revalidate_instances`
  defaults to `never`) and serializes `substitute: false` — the "a
  config claiming a replication cannot parse" guarantee covers PARSING
  only, not instance injection. Sharpening: the SAME attack on the costs
  block (`Level3CostConfig.model_construct(one_way_bps=P(-50))`) IS
  caught by `Level3Config` construction (probe 5b) — the config layer's
  protection against `model_construct` smuggling is inconsistent, and
  the A-004 field is on the UNprotected side. The result manifest stays
  honest (model-side), so severity is config-provenance-forgery only.
- **N-2 (a "risk model" that shapes nothing is manifest-stamped, probe
  6a):** a `risk_model:` block with no consumer (no `target_volatility`,
  no `risk_aversion`, no covariance penalty) produces a book bit-
  identical to the risk-free solve, yet `Level3Result` still carries the
  substitute manifest and a `predicted_volatility`, and
  `decompose_effects` reports a `risk_control_effect` of exactly 0.0 on a
  manifest-stamped "L3_risk_controlled" stage. The numbers are honest
  (0 effect), but a report built from this would show an A-004 risk-
  control stage that controlled nothing. Recommend a warning when a
  risk model is supplied but no constraint/penalty consumes it. Also:
  the `adv_participation` constraint report row carries `value = max
  excess in weight units` (e.g. `−49.2`, slack `49.2`) rather than the
  natural participation fraction, unlike every other row — misleading
  for the reporting layer.
- **N-3 (a feasible set is mislabelled "infeasible" under alpha
  scaling, probe 3a):** alphas scaled ×1e3..×1e6 (a units error a caller
  could make under A-G035-07, which explicitly makes scaling "the
  caller's contract") make SLSQP fail with "Positive directional
  derivative for linesearch" on a PERFECTLY FEASIBLE constraint set; the
  typed refusal then asserts "constraint set infeasible or
  ill-conditioned" naming gross equality (violation ~0.02). Loud and on
  the honest side (no bad book escapes), but the diagnosis claims an
  infeasibility it did not establish. Recommend distinguishing solver
  ill-conditioning (rescale-and-retry, or a distinct typed error) from
  genuine infeasibility.

## Observations (attacked and held; no keeper needed)

- **Wash detection is genuine.** Single-name and all-zero gross-equality
  configs refuse with `genuine gross 0.000000`; a cost-dominated
  gross-equality config refuses naming the competing terms;
  `upper_bound` mode collapses a cost-dominated book to EMPTY (gross
  0.0), never fake leverage — the "upper_bound is wash-free" claim
  holds.
- **Non-convergence cannot escape as converged.** `maxiter=1` on a
  feasible set raises `InfeasibleConstraintSetError` with the
  most-violated constraints named; `result.success` is checked before
  any book is returned.
- **Cost reconciliation is exact** against the merged G034 `CostModel`
  (`totals.linear`) on an asymmetric-leg rebalance with a forced close
  and a no-trade name — `estimated_cost * NAV == charge` to rel ≤ 1e-9;
  the A-G035-10 per-side rate base is confirmed (not the 2x-ambiguous
  half-reading). Negative rates are refused at config on every path
  tried (direct + `model_construct`).
- **Effect additivity is exact** (residual 0.0) at alpha scales 1..~100;
  the telescoping construction leaves no accumulation room.
- **Determinism** holds across input order and PYTHONHASHSEED ∈
  {0, 42, 31337} (bit-identical `float.hex` weights).
- **Manifest `__post_init__` teeth:** `substitute=True` without the
  A-004 id refuses at construction; the `object.__new__` bypass is
  generic Python (not a G035 surface), recorded only.
- **NaN-volatility edge not cleanly reachable:** the numerically-negative
  eigendirection of the probe-2d covariance yields quad 1.4e-34 → vol
  4e-17, not NaN; a genuine NaN would surface loudly in `_final_checks`.
