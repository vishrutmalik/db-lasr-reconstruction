## Findings so far

### RT-G035-1 — forced-close ADV breaches are blessed inside an
absolute weight-unit tolerance, and forced closes are absent from the
post-solve constraint verification (NON-BLOCKING, ratchet planned)

**Where:** `level3_optimizer.py` `_prepare` (pre-solve forced-close ADV
check) + `_final_checks` (adv_participation row covers optimized names
only).

**Mechanism.** The forced-close ADV check is
`abs(exit_weight) > cap + constraint_tolerance` with
`cap = adv_notional * participation / nav` in WEIGHT units and
`constraint_tolerance = 1e-6` ABSOLUTE. The cap scales with `1/nav`;
the tolerance does not. The claimed "independent post-solve
verification of every constraint" never revisits forced closes — the
`adv_participation` report row is `max(|w - w_prev| - t_upper)` over
OPTIMIZED names only.

**Evidence (probe 1).**
- nav 1e9, ADV 1e5, participation cap 5%: a forced close trading
  $5,900 (5.9% of ADV, **1.18x the cap**) builds with no error and no
  `adv_participation` entry for the exiting name.
- nav 1e12, ADV 1e4: a forced close trading $900,000 — **90x the
  entire ADV, 1800x the cap** — is blessed (cap weight 5e-10 vs
  tolerance 1e-6).
- Teeth held: an exit beyond `cap + tol` raises the typed named
  conflict.

**Impact.** Illiquid universe-exiting names at large NAV can breach
participation limits by orders of magnitude, silently, on exactly the
trades (forced closes) where participation risk is worst. Fix
direction: tolerance relative to the cap (or in currency units), and
include forced closes in `_final_checks` / `constraint_reports`.

### RT-G035-2 — A-004 manifest forgery: the optimizer trusts
`is_substitute` but propagates `manifest` with no cross-check
(NON-BLOCKING, ratchet planned; = verifier NB-1, sharpened)

**Where:** `level3_optimizer.py` `_prepare` (gate) + result assembly
(`risk_model_manifest=risk_model.manifest`).

**Mechanism.** `_prepare` checks only `risk_model.is_substitute`; the
manifest copied verbatim onto `Level3Result` (and, downstream, onto
decomposition stages / reports per the A-004 banner discipline) is
never checked for consistency. A hostile `RiskModel` with
`is_substitute=True` and
`RiskModelManifest(name="axioma_v4_replica", substitute=False,
assumption_id=None, shrinkage_intensity=None, ...)` passes every gate:
`substitute=False` skips the `__post_init__` A-004 requirement, and
`shrinkage_intensity=None` skips `_prepare`'s intensity cross-check
(`if delta is not None`). Probe 2a: a vol-capped (risk-bearing) book
built whose manifest denies being a substitute — the exact G020-B4 /
RT-G028-5 banner-stripping shape the three-layer labelling claims to
prevent.

**Fix direction:** `_prepare` must refuse
`risk_model.is_substitute != risk_model.manifest.substitute` (and
consider requiring a non-None intensity for `kind=
"shrinkage_substitute"`).

### RT-G035-3 — rank-deficient / zero-variance covariance turns the
hard `target_volatility` cap into fake risk-free leverage
(NON-BLOCKING, ratchet planned)

**Where:** `level3_risk.py` (no rank/eigenvalue guard) +
`level3_optimizer.py` (vol cap and risk penalty trust `sigma` blindly;
alpha maximization ACTIVELY seeks the null space).

**Evidence (probe 2c/2d).**
- Two constant-return names (sample variance exactly 0, legal panel):
  optimizer builds `{Z1: +1.0, Z2: -1.0}` — 2.0 gross, expected alpha
  0.10 — with `predicted_volatility == 0.0`, blessed under a **1 bp**
  annualized vol cap.
- `shrinkage_intensity=0` (legal config: "0 = sample") with T=3 < N=4
  collinear histories: eigenvalues `[-1.3e-19, -8.2e-37, 6.4e-20,
  4.0e-3]` (PSD only to float noise); optimizer loads the null space
  for a 2.0-gross book with alpha 0.0675 at predicted vol == the 1 bp
  cap.

**Impact.** The realistic shape is delta=0 with monthly histories
(T≈60) on universes of hundreds/thousands of names — the null space is
then enormous and the vol cap is unenforceable while REPORTING
enforcement. Fix direction: refuse (or warn loudly) when a vol cap /
risk_aversion consumes a covariance with `n_obs <= n_securities` at
delta=0, or floor the minimum eigenvalue / refuse zero-variance names.

## Non-blocking notes so far

- **N-1 (config smuggle, probe 2b):** `RiskModelConfig.model_construct(
  substitute=False, ...)` is accepted by `Level3Config` (pydantic v2
  `revalidate_instances` default `never`) and serializes
  `substitute: false` — the "a config claiming a replication cannot
  parse" claim covers parsing only, not instance injection. The RESULT
  manifest stays honest (model-side), so severity is
  config-provenance-forgery only.
- **N-2 (adv report units, probe 1a):** the `adv_participation`
  constraint report row carries `value = max excess in weight units`
  (e.g. `-49.2` with slack `49.2`) — unlike every other row, `value`
  is not the constraint's natural quantity (participation fraction),
  making the report row unreadable/misleading for the reporting layer.
- **N-3 (feasible set mislabeled infeasible under alpha scaling,
  probe 3a):** alphas scaled by 1e6 (units error a caller could
  actually make, A-G035-07) make SLSQP fail with "Positive directional
  derivative for linesearch" on a PERFECTLY FEASIBLE constraint set;
  the typed refusal then claims "constraint set infeasible or
  ill-conditioned" naming gross equality (violation 0.023). Loud and
  honest-side, but the diagnosis asserts infeasibility it did not
  establish.
