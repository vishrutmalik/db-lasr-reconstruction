## D-020 transport rulings — verified implemented (item 3)

- **(a) FULL 64-hex sha256:** `request_hash` returns the full hexdigest;
  capture ids = full sha256 of uncompressed bytes; grep across the
  package finds NO identity truncation (the only slices are the 2-char
  directory shard prefix — full hash remains the dir name — and the
  jitter derivation, which is not an identity). Regex test
  `test_full_64_hex_never_truncated` + on-disk layout test confirm.
- **(b) errors never replayed as success:** `latest_success` filters on
  `2xx` (`is_success`), `replay()` routes through it and raises a typed
  `FactSetCacheMissError` otherwise. Verifier probe: error-only cache →
  replay raises, `latest_success` is None. Unit tests
  `test_error_never_replayed_as_success`, `test_success_after_error_serves_success`
  confirm. Error evidence policy: 401/403 evidence blocks quota-free
  until TTL/force_refresh (traced code + tests); retryable/expired
  evidence never blocks (probe + tests).
- **(c) FACTSET_TRIAL_DATA_ROOT:** required in live mode (typed
  `FactSetDataRootError`), absolute + existing-dir enforced,
  `Path.resolve()` defeats symlink laundering — verifier probes: a clean
  symlink whose target is inside a `OneDrive-*` dir is REFUSED; a
  symlink into the repo is REFUSED; case-insensitive
  onedrive/cloudstorage fragments on the RESOLVED path. Replay mode:
  explicit `cache_root` required, no silent default.
- **(d) dual gate + kill switches:** `live_gate_open` checks kill
  switches (config then env) FIRST, then config `transport.live`, then
  env `FACTSET_LIVE` — correct precedence; a committed config alone can
  never go live; `build_transport` raises `FactSetKillSwitchError` on a
  half-open gate (never a silent replay downgrade). **Replay cannot
  construct a network sender:** verified by poisoning `sys.modules["httpx"]`
  (replay build + typed miss with httpx unimportable) AND by injecting a
  hostile sender that raises on any call (never called). `HttpxSender`
  is constructed only inside the live branch of `build_transport`;

## Findings

### BLOCKING

- **VF-FS010-1 — vendor-echoed credential values persist UNSANITIZED in
  the capture index (`meta.json`).** `transport._store_guarded` passes
  the parsed `ErrorDetail` (raw envelope `messages`/`sub_errors`/`codes`)
  to `cache.store`, which writes it into `meta.json` without passing it
  through the transport's `Sanitizer` — verified by probe: a 401 body
  echoing a canary API key landed verbatim in
  `<root>/symbology/<hh>/<hash>/meta.json`, while the raised error
  message and telemetry were correctly sanitized. This violates the
  package's own declared contract (sanitize.py: values never in
  "captures, manifests"; test_factset_transport.py's own comment:
  "secrets must never reach index files") on the security-critical
  transport goal. The existing canary test misses it because its error
  bodies contain no secret. Exposure is bounded (file lives outside git
  under the licensed data root, next to the verbatim .json.gz that
  necessarily holds the same bytes) — but meta.json is the index that
  FS011+ tooling and evidence citations will quote. **Fix:** sanitize
  `detail` (e.g. `sanitizer.clean_tree(detail.as_record())`) before
  store, and extend the canary test to plant the canary in an error
  body. The parallel red-team's in-progress leakage test independently
  asserts the same invariant.

### NON-BLOCKING

- **VF-FS010-2** — budgets are checked once per `execute()`, not per
  attempt: a retry loop can overshoot the daily/per-endpoint budget by
  up to `max_attempts-1` live calls (probe: 3 sends with daily budget
  2). Bounded and ledger-recorded (next execute stops), but "typed hard
  stop" semantics would re-check inside `_send_with_retries`. Owner:
  FS010 follow-up or FS011 hardening.
- **VF-FS010-3** — batch `_probe` (status/result polls) records to the
  ledger but never calls `check_budgets` and bypasses endpoint policy;
  bounded only by `poll_timeout` (~40+ probes at cap). UNREACHABLE live
  under the committed FS010 config (no batch endpoints enabled) — MUST
  be fixed before FS012 enables fundamentals batch. Owner: FS012
  charter line (orchestrator).
- **VF-FS010-4** — live-gate consent token is whitespace-lenient:
  `FACTSET_LIVE=" 1 "` opens the gate via `.strip()`. Kill-switch
  leniency is fail-safe; consent leniency is not symmetric-risk.
  Recommend exact-match `"1"` for `FACTSET_LIVE`. (Red-team's parallel
  in-progress test asserts the strict reading; final classification is
  theirs.) Owner: FS010 follow-up.
- **VF-FS010-5** — canonical-JSON encoder triplication without an
  equivalence pin (see item-8 ruling above). Owner: FS010 follow-up
  (test-side pin) + FS009/architect (shared-layer ruling; already
  flagged in DESIGN.md).
- **VF-FS010-6** — `.env.example` (G018, main) lacks the seven
  FACTSET_* env names; the file is not FS010-owned so the omission is
  correct scope discipline, but the names should be added. Names ARE
  durably documented (sanitize.py table + trial.yaml header). Route:
  orchestrator (grant to FS011 or a coordination commit).
- **VF-FS010-7** — coordination hygiene: PR #84 body still says the
  live smoke is UNRESOLVED while branch tip 462fa90 records an executed
  smoke; the IMPLEMENTED report cited 2d6cba5 while the tip moved
  (docs-only delta). PR body should be refreshed at merge. Route:
  orchestrator.
- **VF-FS010-8** — register candidates to record (route: orchestrator,
  assumptions/contradiction registers): (i) conservative 5rps/5conc
