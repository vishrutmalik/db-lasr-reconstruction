## Re-probe results

### VF-FS011-1 — mapped-or-explained accounting: CLOSED

`seed_securities` now derives operation-specific accounting. An entity-only
row with no usable `fsymSecurityId` emits no seed and is `NOT_COVERED`, never
`SUCCESSFULLY_RETRIEVED`. A historical request containing a value without an
`outputType` becomes `VENDOR_API_FAILURE`, and every row for that request id is
excluded from hydration rather than partially blessed. Fresh current and
historical keeper probes pass.

### VF-FS011-2 — typed response boundary: CLOSED

Current and historical rows must echo the exact requested
`inputSymbolType`; missing and mismatched echoes refuse. Current fsym outputs
are also normalized and checked against their declared level markers before
accounting. Fresh missing/mismatch and `-E`/`-R`/`-L`-as-security probes pass.

### VF-FS011-3 — historical normalization and validation: CLOSED

Historical `outputType` is mapped to a declared identity scheme, the value is
normalized and structurally validated, and `IdentifierInterval` enforces the
same canonical pair before duplicate checks. Lower/upper ticker variants can
no longer evade an overlapping-ownership refusal; malformed schemes and
values refuse.

### VF-FS011-4 — interval semantic validity: CLOSED

Both bounds are parsed eagerly while the original valid strings remain
verbatim. A closed interval with `startDate > endDate` is quarantined before
it can weaken overlap detection. The conservative unknown-open-end policy is
unchanged.

### VF-FS011-5 — conflicting fsym re-seed: CLOSED

Only an exactly equivalent `SecuritySeed` reassertion is idempotent. Any
different entity, regional, listing, or enrichment claim for an existing fsym
raises `DuplicateIdentityError`; distinct-fsym mint collisions remain typed
refusals.

### RT-FS011-06 — unrequested historical output injection: CLOSED

Each historical row's `outputType` is matched case-insensitively against the
exact request output set before accounting or hydration. A CUSIP row in a
tickerRegion-only request refuses rather than entering the identity map.

### RT-FS011-07 — favorable-row bridge selection: CLOSED

The bridge examines all intervals covering the retrieval date. More than one
distinct canonical tickerRegion value yields
`FALLBACK_CROSSCHECK_DISAGREE`; one matching row cannot override a
contradictory covering row.

### RT-FS011-09 — casefold last-wins ambiguity: CLOSED

Current dynamic output keys are folded through an ambiguity-preserving
boundary. Conflicting non-null/non-null and null/non-null case variants refuse
in either ordering; equivalent values collapse to one logical output; a
single differently-cased key retains D-6/U-5 behavior. The generic
`CUSIP`/`cusip` probe passes as well as the fsym-specific probes, showing the
repair is not special-cased to `fsymSecurityId`.
