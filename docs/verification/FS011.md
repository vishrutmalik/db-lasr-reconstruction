# FS011 verification — symbology adapter and identity spine

**Verdict: FAIL (remediation + fresh reverification required).** Reviewed the
implementation at the immutable revision
`e149a9815ce02e9ef8b220826b5f86b708d1b4f8`, never a moving branch tip. Its
merge base with `main` is `e5634049694787dde9530ecfb1dd881b0f66c2b5`; the
complete reviewed delta is 7 added files / 3,716 lines. No live API call was
made and no credential file was read.

The basic design is substantially right: requests are caller-typed and grouped
by declared scheme, fsym level markers are checked, request ids are normalized
and deterministically chunked, v2 minting is deterministic and domain-tagged,
historical lookup is fsym-seeded and outward-only, bridge disagreement falls
back to v1, transport errors remain typed, and `ad12800` correctly prevents a
historical HTTP 403 from being misreported as a content failure. The clean
existing suite does not cover five identity-integrity failures below.

## Evidence and gate ruling

The governing chain was read from the bootstrap and current main control
plane: the FS011 durable charter, architecture §5, MANIFEST identity semantics
and FS-VQ-23..28, D-018..D-020, the implementer checkpoint, and F-009..F-011.
Those sources require both code correctness and a green WP2 battery including
historical-ticker resolution, inactive resolution, duplicate integrity, and
seven-way mapped-or-explained accounting.

Three distinct propositions must not be collapsed:

1. **Classifier correctness:** `ad12800` is correct. A forbidden historical
   endpoint means `UNRESOLVED/not_entitled`; it is not evidence that ticker
   history is wrong. The replay keeper for the observed 5-current-200 /
   3-historical-403 shape correctly produces `PASS_WITH_UNRESOLVED` and marks
   `content_assessed=false`.
2. **Observed entitlement:** F-011 proves current `/identifier-resolution`
   was entitled at 2026-08-18T05:33:24Z and historical
   `/historical-identifier-resolution` was not. This is timestamped endpoint
   evidence, not a cause claim and not permanent entitlement.
3. **Content verification / acceptance:** historical intervals, META/FB
   ticker-change content, and historical duplicate claims were not observed.
   `PASS_WITH_UNRESOLVED` therefore **blocks the existing FS011 acceptance
   gate**. The durable charter says “historical tickers resolve” and
   `Complete = battery green + reports`; it does not authorize an entitlement
   waiver. The code may preserve an honest unresolved state, but FS011 cannot
   be VERIFIED/MERGE_READY until the historical acceptance arm is observed
   green or the orchestrator/user explicitly amends the charter.

## Blocking findings

### VF-FS011-1 — seven-way accounting can say success while the identity is silently dropped

`resolve_current` assigns `SUCCESSFULLY_RETRIEVED` when *any* requested output
is non-null (`symbology_adapter.py:219-225`). `seed_securities` then silently
skips a row lacking `fsymSecurityId` (`:340-348`) without changing or adding
accounting. A fresh adversarial probe returned a valid `fsymEntityId` but no
security-level id: the result was **zero seeds** plus
`successfully_retrieved`. Thus `build_identity_map` can omit a requested id
while its silent-loss gate says it was mapped. The historical analogue also
exists: a row with a non-null value but null `outputType` is counted as
success (`:289-295`) and then skipped during hydration (`:387-389`).

This violates the charter's “every id mapped-or-explained (7-way accounting)”
gate. Account the seed/hydration outcome actually required by the operation;
missing `fsymSecurityId` or an unusable historical row must be typed and
explained, never retained as a successful map.

### VF-FS011-2 — response scheme confusion is accepted at the typed boundary

The response parser turns a missing `inputSymbolType` into `""`, and the
adapter checks only that `requestId` was requested. It never verifies that the
non-nullable echoed input scheme matches the request's declared scheme. A
fresh probe requested `tickerRegion:AAPL-US`; a response echoing
`inputSymbolType=CUSIP` was accepted as successfully retrieved. The same hole
exists on historical rows.

D-020(b)'s typed entrance cannot end at the request builder: refuse a missing
or mismatched response echo before accounting or hydration. Validate returned
fsym/output levels at the same boundary as well.

### VF-FS011-3 — historical identifiers bypass normalization and structural validation

`IdentifierInterval.__post_init__` validates only dates. It accepts an
arbitrary `id_scheme`, blank/malformed `id_value`, and noncanonical casing;
`hydrate_identity_map` passes the vendor value through unchanged. Duplicate
detection compares `(id_scheme, id_value)` case-sensitively. A fresh probe
successfully assigned overlapping `ticker:meta-us` and `ticker:META-US` to two
different securities, evading `DuplicateIdentityError`.

Normalize and validate each historical output according to its declared
`outputType` before storage and collision checks. This is required by the
tickerRegion casing policy and the no-silent-duplicate gate.

### VF-FS011-4 — inverted validity intervals are accepted and weaken overlap detection

ISO parsing checks syntax but never enforces `start <= end`. A fresh probe
stored `[2025-01-01 .. 2020-01-01]`. Such a row can make `_overlaps` return
false and let a conflicting identity claim pass. Quarantine inverted bounds
before they enter the map; preserve raw strings only after semantic validity
is established. Keep the conservative open-end treatment until U-7c is
observed.

### VF-FS011-5 — a conflicting re-seed of one fsym is silently ignored

`IdentityMap.seed` returns the first seed whenever the normalized
`fsymSecurityId` already exists, without comparing entity/regional/listing
edges. A fresh probe seeded `DDDDDD-S` first with `AAAAAA-E`, then with
`BBBBBB-E`; the second cross-API identity claim disappeared silently. Only an
exact equivalent reassertion should be idempotent. Conflicting fsym edges must
raise a typed integrity error (or be represented as explicit dated
multiplicity where the model supports it).

## Non-blocking observations / retained uncertainties

- `_refuse_ambiguous_current` refuses conflicting duplicate rows but retains
  exact duplicate rows in the returned tuple. Downstream consumers should not
  receive duplicate grain even when payloads match; add a reject-or-dedupe
  contract and a keeper.
- A chunk-level 403 is assigned to every id as `NOT_ENTITLED`. That is honest
  for the observed endpoint-wide F-011 refusal, but per-identifier 403 behavior
  remains documented. Until isolated live evidence exists, the reason must
  continue to say “chunk refusal” and must not be promoted to proof that every
  id is independently unentitled.
- `mint_security_id_v2` matches its pinned formula and normalized-input tests;
  `IdentityMap` checks same-map truncated-digest collisions. The lower-case
  sentinel provides protocol/domain separation from the v1 payload, not a
  mathematical proof that two 48-bit truncated digests can never collide.
- The legacy bridge's dated ticker check and its three fallback classes are
  semantically honest. A historical 403 becomes
  `FALLBACK_CROSSCHECK_UNVERIFIABLE`, not a false bridge success.
