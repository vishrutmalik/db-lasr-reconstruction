## Blocking findings

### VF-FS024-1 — one bundled 403 cannot answer the per-output-type question

`build_probe_plan` constructs one Symbology request containing all three gated
output types (`CUSIP`, `ISIN`, and `SEDOL`) at once
(`discovery.py:277-290`). FS-VQ-02 explicitly requires probing **each output
type** (`MANIFEST.md:277`). A 403 for the combined request proves only that the
combination was denied; it cannot identify which one or more requested types
caused the refusal. Nevertheless the machine manifest records
"CUSIP/ISIN/SEDOL outputs HTTP 403" (`manifest.json:327`), and the human
fold-in and implementer checkpoint repeat the individual-looking conclusion.
This violates the requested no-overgeneralization rule and leaves FS-VQ-02
unanswered.

Required remediation: retain the bundled capture as request-specific evidence,
but classify all three individual types as unresolved until three separately
hashed one-output-type probes are made under a new bounded/live-authorized
acquisition. Update tests so one type's denial cannot label the others.

### VF-FS024-2 — cached account HTTP 401 is converted into endpoint entitlement

The offline evidence classifier maps both 401 and 403 to endpoint
`Unauthorized` (`discovery.py:498-504`). Live `FactSetAuthError` correctly
propagates and invalidates the run, but replay first receives a cache miss,
looks up the latest error capture, and applies this mapping. An independent
synthetic cache probe reproduced: HTTP 401 -> `Unauthorized`, `from_cache=True`,
0 live calls. Under F-009, 401 is account-authentication evidence; it cannot
support an endpoint entitlement conclusion or family summary.

Required remediation: distinguish account authentication (401) from operation
authorization (403). Replay should abort/return an explicit account-level block
or `Requires clarification`, suppress per-endpoint/family entitlement claims,
and include a regression test with cached 401 evidence.

### VF-FS024-3 — the final cache-first pass overwrote the live acquisition manifest

`run_discovery` always builds and writes
`runs/<run_id>/manifest.json` when outputs are enabled
(`discovery.py:744-758`), while `write_run_manifest` uses unconditional
`write_text` (`run_manifest.py:82-100`). The final fold-in reused
`fs024-live-discovery-20260818`, overwriting the acquisition record. The
persisted file now reports `live_calls=0`, `cache_hits=14`, an empty
`entitlement_results` object, and an empty `raw_capture_sha256` list. It cannot
audit the claimed 14-live-call acquisition and contradicts the run-manifest
contract that records request metrics, entitlement outcomes, and capture
checksums for every trial execution.

Required remediation: use immutable unique run IDs per execution (or refuse an
existing run directory), preserve the original acquisition manifest, and write
a distinct replay manifest with explicit references to the evidence it
consumed. Add a two-pass regression proving the acquisition manifest cannot be
overwritten or stripped of capture/entitlement lineage.

- **VF-FS024-5 — family labels can overgeneralize future samples.**
  `_family_verdict` emits plain `Unauthorized` when every sampled probe is
  unauthorized (`discovery.py:866-879`). No current family hits that branch,
  but the label should say "all sampled probes unauthorized" and preserve the
  fact that unprobed operations remain unknown.
- **VF-FS024-6 — replay requires a writable evidence root.** Even cache hits
  call `_emit`, which writes telemetry under `raw/_telemetry`. The verifier's
  read-only external cache failed in place and required an isolated writable
  copy. Consider a separate telemetry sink or a genuinely read-only replay
  mode; the notebook computation itself is otherwise deterministic and
  network-free.
- **VF-FS024-7 — budget comments drifted.** `trial.yaml` comments claim policy
  sums of 59 and 74 (`trial.yaml:68,88`); the configured sum is 78. Runtime
  limits and tests use the correct values, so this is documentation-only.
