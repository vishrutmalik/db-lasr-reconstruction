  `lasr_hf_2014` two-sub-model blend (z-scored Weekly + Technical, equal
  weight — not equivalent to equal-weighting 8 experts) or the `nlasr_2012`
  ultra variant; variant-override mechanics exist only as comments. The
  docs declare field lists abridged and `ExpertSpec.feature_list_id` gives
  the mechanism, so this is completable at G017/G025 without redesign — but
  it should be made explicit before G025.
- **N-2** Delisting return has two schema homes (`listing_intervals.
  delisting_return`, `corporate_actions.terminal_return`) under a
  "exactly one place to live" claim; G017 must designate the authoritative
  column (CI-049 double-realization risk otherwise).
- **N-3** Worked example `base_bps: {value: 20, prov: EXPLICIT, src:
  "P1-38 grid midpoint convention"}` — 20 bps is not EXPLICIT in P1 (grid
  5–30; 20 is P2/P3's base). Should be ASSUMED/INFERRED; as-is it is a
  small CI-044-spirit blemish and echoes CR-013's cross-paper-cost warning.
- **N-4** `TimingRecord` lacks an explicit holding-period end; MP §23
  distinguishes holding from target period, and for `nlasr_2020` (1-week
  hold, 4-week target) they differ. Derivable from the rebalance grid;
  recommend an explicit field or documented derivation.
- **N-5** `trading_calendars` has no knowledge_time yet U1 covers every
  PIT-reachable table (PitStore.calendar reaches it); `securities` uses
  `first_knowledge_time`. Add explicit U1 exemptions/naming note.
- **N-6** Missing PK/sort keys on six tables (see executability probe #1).
- **N-7** `ComponentSpec` (config doc) vs `ExpertSpec` (training doc)
  relationship undefined.
- **N-8** Toolchain proposal omits the uv bootstrap path for a machine with
  no brew (standalone installer → `~/.local/bin`, consistent with the
  existing `gh` precedent); G016 should record it.
- **N-9** Guard table pins `selection.type == "min_z"` for
  `nlasr_2012`/`nlasr2_2013` but not for the `lasr_2014` family, though
  CR-008 assigns argmin-Z there too; the CI-029 config-diff test would
  likely catch drift, but the guard should be explicit.

  two-way turnover ">250%/yr"; `nlasr_2012.md` and the worked config say
  per month (P1-37's quote carries no unit). Reconcile in the methodology
  docs before G027/G028 encode the band — not a G015 defect.
