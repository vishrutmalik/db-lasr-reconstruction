## Amendment rulings (verifier recommendation to orchestrator)

**A. `UnknownProviderIdError` — RECOMMEND ACCEPT.** §3 forbids returning an
empty frame to signal absence, and none of the four documented errors covers
entity resolution (`CapabilityError` = declared-false capability;
`FieldUnavailableError` = field level; `HistoryUnavailableError` = window;
`IntegrityError` = malformed payload). The local provider *can* authoritatively
distinguish "unknown entity" from "valid-but-empty", so a typed refusal is the
honest behavior, and CT-12's absence branch already depends on it. Amend
provider_contract.md §3 to add the class (and note NB-6/NB-8 while there) so
spec and code stop diverging.

**B. Failed-basis downgrade to `SNAPSHOT_STAMPED` — RECOMMEND ACCEPT, with one
condition.** Leak-safety reasoning: `SNAPSHOT_STAMPED` forces
`knowledge_time = retrieval_time` (D-009), and retrieval necessarily happens
after every bar in the retrieved window closes, so the downgrade can only
*delay* the as-of availability of the data relative to `RETRO_WINDOW`
(knowledge at bar close) — a monotonically conservative move with no
early-knowledge channel. The orthogonal FM-17 risk (back-adjusted price
*values* embedding future corporate actions) is not solved by any grade, and
is separately guarded: the acknowledgment flag that flips the grade to
`RETRO_WINDOW` is exactly the CT-15 canonical-layer acknowledgment, so the
downgrade cannot bypass that guard, and "nothing downstream may upgrade the
grade" holds (no upgrade path exists in code). Condition: the docstring
promises the downgrade is "recorded in the manifest, not silent", but nothing
enforces that yet — when ingestion/manifests land (G020/G021), the downgrade
event MUST be manifest-recorded and surfaced, otherwise a misconfigured run
degrades observably-silently (MP §26 adjacency). Amend provider_contract.md
§1/D-011 to state the failed-basis outcome and the manifest-recording
requirement explicitly.
