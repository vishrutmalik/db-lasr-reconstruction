## Adversarial probes (verifier's own, outside tests/)

awkward instant (`2021-03-17T14:33:27.123456Z`). Results:

- **(b) future restatement:** restatement with knowledge_time 45 days after

  pinned datasets); becomes visible exactly at its own knowledge_time. PASS.
- **(c) silent D-015 downgrade unconstructible:** manifest payload with

  subsequent read and `verify_manifest_payload` flags the on-disk JSON with

- **(d) on-disk tamper:** flipping a persisted manifest's `pit_grade` to
  `SYNTHETIC_TRUTH` → quality audit returns the D-011 disagreement problem.
  PASS (also re-ran the committed integration tamper test).
- **(e) idempotency:** re-ingesting the identical raw payload (different
  retrieval_time, reversed record order) → `created=False`, same snapshot_id,
  exactly one snapshot on disk, FIRST retrieval_time authoritative; canonical
  rewrite of identical content → no-op. PASS.
- **(f) brute-force oracle on a degenerate panel:** three rows sharing ONE
  knowledge_time within an event key (U2-forbidden degenerate input) plus a

  history as a fresh pinnable dataset; the error is loud and names the row.
  The trade-off (an old pipeline run is no longer a silent no-op after a

## Corporate-action ledger recomputation (CI-049)

Recomputed by hand from the fixture numbers, independently of the test code:

- **2:1 split** (ex 2024-03-04; closes 100.0 → 50.0): `split_factor_cum` =
  2/1 = 2.0; adjusted 100.0×1.0 = 100 vs 50.0×2.0 = 100 → return 0 exactly.
  Matches the test's assertions at `abs=1e-12` (exact-arithmetic identity per
  the criteria tolerance conventions).
- **Cash dividend 1.0** (ex 2024-06-03; prev close 50.0, ex close 49.0):
  factor 2.0 × (1 + 1/49); prev_adj = 50×2 = 100, ex_adj = 49×2×(1+1/49) =
  98+2 = 100 → adjusted return 0 == economic total return (49+1)/50 − 1 = 0.
  The general identity holds algebraically: adjusted return over the ex-date
  = (close_ex + D)/close_prev − 1 for any inputs — the factor convention is
  exact, not approximate.
- **Same-day split+dividend** compound into one row (PK-correct); the product
  is order-independent, and the dividend uses the post-split ex-date close —
  hand-checked: holder of 1 pre-split share ends with 2×50 + 2×1 = 102 → 2%,
  matching 2.0×(1+1/50).
- **N-2 semantics:** `corporate_actions.terminal_return` is the single
  authoritative home; `derive_delisting_returns` populates the derived
  `listing_intervals` view once, refuses ambiguity (two candidate intervals →
  error), and a delisting without terminal_return is a no-op. Builders write
  `delisting_return=None` (derived-view-only), consistent with N-2.

## Non-blocking findings

1. **NB-1** — `tests/unit/test_pit_asof_property.py::test_asof_monotonicity_property`
   compares `brute_force_latest` to itself (oracle vs oracle); the
   implementation is not in the loop. Implementation-level monotonicity IS
   covered by `test_ci002_asof_monotonicity_never_removes_known_rows`.
   Recommend pointing the property test at `select_latest_vintages`.
2. **NB-2** — `CanonicalStore.write` persists a manifest forged via pydantic's
   `model_construct` (validation-skipping escape hatch). Both catch nets work
   (`read_manifest` raises `StoreError` on every read; `verify_manifest_payload`
   flags the on-disk JSON), so there is no silent path — but a one-line
   defense-in-depth re-validation (`type(manifest).model_validate(
   manifest.model_dump(mode="json"))`) in `write` would close the write-side
   gap. Candidate for G021.
3. **NB-3** — unknown table in `PitStore.as_of_frame` raises builtin
   `KeyError` (from `get_schema`) although `PitQueryError`'s docstring claims
   the unknown-table case; cosmetic error-typing inconsistency.
4. **NB-4** — `join_latest_known` silently localizes naive datetimes as UTC
   via `pd.to_datetime(utc=True)`, while the PitStore path rejects naive
   timestamps through `ensure_utc`. Convention inconsistency in a public
   utility; recommend an explicit naive-rejection or a documented exception.
5. **NB-5** — `CanonicalStore._check_max_knowledge_time` skips the
   manifest-vs-observed comparison for empty record batches (a 0-row dataset
   could claim any `max_knowledge_time`). Marginal; builders reject empty
   batches anyway.
