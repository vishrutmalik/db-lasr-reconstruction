### A-G026-01 ruling (purge strict at A) — DEFENSIBLE, correct

CI-015(b) removes "training rows whose target window intersects the test
period". Return segments are half-open `(start, end]`; per CI-012 every
test outcome starts STRICTLY after its decision, so test outcomes occupy
`(A, B + H]`. A training window ending exactly AT A shares zero return
segment with any test outcome. CI-010's own formalization (`target_end <=
fit_as_of`, from P3-23 "we use the data up to three months prior to the
rebalance date") legalizes equality — DB's freshest training row is exactly
the one whose window ends at the fit/rebalance instant, and P1-19/P1-22
(trailing 12 months, retrained monthly) imply the same boundary. Excluding
the ==A row would deviate from the papers being reconstructed with no
leakage benefit.

### A-G026-02 ruling (post-test-only embargo) — DEFENSIBLE, correct

CI-015(b) literally says "an embargo of at least one full horizon **after
the test period**". The pre-test side is fully governed by the fit boundary
(CI-010/015a) + purge (015b first clause): any pre-test training window
sharing a segment with a test outcome is already purged. A symmetric
pre-test embargo would exclude training windows ending within one horizon
BEFORE the test start — i.e., forbid exactly the P1/P3 training sets
(P3-23, P1-19/22 checked in the evidence rows: training runs to windows
ending AT the fit date). I additionally verified by grid arithmetic that at
e=1 on a same-grid family, purge + embargo together exclude EXACTLY every
training window sharing a return segment with any test outcome (a train row
k grid steps after B starts at `B + realized-duration(B→d)`; escape from the
zone implies start ≥ test-window end — no shared segment), as the module
docstring claims. Caveat: the skill's own invariant line conflicts with
this (non-blocking finding 2).
