  is upstream (G020/G026). Schedule validation forbids marks at or before
  the rebalance date and rebalances before the previous period's last mark —

## Non-blocking recommendations

1. **N-1 (tolerance mismatch, cosmetic):** the engine's runtime guard
   `RECONCILIATION_TOLERANCE = 1e-9` is looser than CI-045's 1e-10. Tests
   bind 1e-10 everywhere and observed residuals are ~1e-16, so nothing is
   gamed, but a residual in (1e-10, 1e-9] would pass at runtime and only be
   caught by a downstream CI-045 re-assertion (G029). Suggest tightening the
   constant to 1e-10 or documenting why the runtime guard differs.
2. **N-2 (duplicate terminal events tolerated silently):** a second
   `terminated` event for an already-terminated, non-held id is a no-op
   (exactly-once realization holds; no phantom P&L — probed). CI-049 is not
   violated, but an upstream data-layer inconsistency is swallowed; a typed
   or logged rejection would be louder. Owners' call.
3. **N-3 (`apply_position_caps` precondition):** the public function does not
   renormalize inputs whose sum ≠ `side_total` (documented "approximately"
   precondition), and its defensive `remaining <= 0` branch can break the
   sum invariant for out-of-contract inputs. The internal caller always
   satisfies the precondition; consider validating it for direct callers.
4. **N-4 (schema gap, already flagged in the PR):** `PortfolioConfig` lacks
   `gross_exposure`/`max_weight` Params, so the P1 "2x" and per-name caps
   enter as explicit `from_config` keywords rather than from the version
   YAML. CI-044-visible either way; shared-file change is correctly left to
   the owners (G043/G029 follow-up).
5. **N-5 (−100% non-terminal return):** a position wiped to exactly zero by
   r = −1.0 without a terminal event is dropped at zero value (books close,
   probed) but the id is NOT banned and may re-enter later targets.
   Defensible (worthless ≠ delisted) but worth a docstring note, since the
   data layer is expected to send such cases as terminal steps.
6. **N-6 (near-circular assertion):** `net_pnl == gross_pnl − cost − borrow`
   in the tests restates the engine's definition; keep the cash-ledger
   assertions (nav_end == 1094.0 etc.) as the load-bearing CI-048 checks —
   they are present and correct.

## Interface reconciliation preview — G027 `CostModel` vs G034 (informational, for G029)

Read-only inspection of `origin/agent/implementer/G034-costs`
`src/lasr/costs/interface.py` (both sides already flag this as a G029
integration item). Exact mismatches the G029 adapter must bridge:

- **M-1 granularity:** G027 passes one aggregate `trades:
  Mapping[str, float]` per rebalance; G034 wants `Sequence[Trade]` with
  per-trade `trade_date`, `region`, `adv_notional`, `spread_bps`. The G027
  hook carries none of that metadata → adapter needs a side channel keyed by
  (security_id, rebalance_date) from the universe layer.
- **M-2 short book:** G027 supplies one aggregate post-trade
  `short_notional: float` + `day_count_fraction: float (>= 0, 0.0 legal)`;
  G034 wants per-security `ShortPosition` marks with `accrual_days: int >= 1`
  plus per-security region/fee overrides and `hard_to_borrow`. Aggregate
  cannot express per-security fees or HTB exclusion; dcf→accrual_days
  conversion needed, and dcf=0.0 has no valid G034 encoding.
- **M-3 borrow base:** G027's short notional is the rebalance-instant
  post-trade snapshot (one hook call per period); A-G034-05 expects
  mark-to-market observations, so borrow on drifted short values is not
  expressible through the current hook.
- **M-4 return shape:** G027 wants `(cost, borrow)` currency tuple; G034
  `run()` returns `CostRunResult` with bucket decomposition,
  `zero_borrow_banner`, and `hard_to_borrow_violations` — the adapter must
  collapse to `(totals.trading_total, totals.borrow)` and route banner/flags
  outside the tuple (the G027 hook has no flag channel).
- **M-5 context:** G027 passes per-period `nav`; G034 `RunContext.aum` is
  run-scoped for size scaling — adapter must pin which one feeds `aum`.
- **M-6 naming:** `CostModel.period_charges` (G027) vs
  `CostModelProtocol.price_trades/accrue_borrow/run` (G034) — zero
  structural overlap; the bridge is a pure adapter, as both PRs state.
