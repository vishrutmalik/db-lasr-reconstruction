## Non-blocking recommendations

1. **Float round-trip semantics of "zero residual":** `net + costs == gross`
   re-addition is 1-ulp inexact for float-unfriendly gross values (verifier
   observed −2.84e-14 at gross = −120.0), while the constructive forms
   (`net == gross − costs` recomputed; deducted ≡ decomposition sum) are
   bit-exact. The shipped test's exact-equality assertions pass only because its
   fixture values are float-benign. Recommend stating the residual convention in
   the `net_of` docstring, and G027/G028 reconciliation should compare
   `gross − costs` against `net` rather than re-adding.
2. **Unknown preset access** raises builtin `KeyError`, not a typed `CostError`
   (no `get_preset` accessor). Loud, never silent — acceptable; a typed accessor
   would help when G029 wires scenario ids from config strings.
3. **`day_count_denominator=0` sentinel** on borrow-free explicit zero records is
   an undocumented magic value; consider `None` or a docstring note.
4. **A-G034-06 traceability:** the p4 sweep grid `Param`s carry
   `prov=INFERRED` with explanatory `src` but `assumption=None`; the A-G034-06 id
   lives only in docstring/register. Attaching `assumption="A-G034-06"` would
   make the register row machine-checkable.
5. `totals_of` vs Σ period rows association-order equality is not asserted by any
   test (held bit-exact on the verifier ledger); a cheap property test would pin it.
6. HTB **exclusion** (before optimization) and the G027 ledger→`Trade`/
   `ShortPosition` adaptation are explicitly deferred (PR reconciliation notes);
   G029/G035 must close them — matches the module's documented scope.
